# embed: notes for agents

`notchling-embed` is the only crate that links candle. It runs granite-embedding-97m-multilingual-r2 on the Mac for hybrid search (design: `docs/superpowers/specs/2026-11-13-hybrid-search-design.md`; plan: `docs/superpowers/plans/2026-11-14-search-p4a-embed-helper-eval.md`). It is off by default and never runs on workers. Accelerate is turned on only under `cfg(target_os = "macos")`; everything else builds and tests on Linux and Windows.

## Why the code is this way

- `src/modernbert.rs`: A copy of candle's ModernBERT (license in `THIRD-PARTY.md`). candle built the attention mask in f32 whatever the weights were, so an f16 or bf16 load failed on the add, and a masked position held `f32::MIN`, which is `-inf` in half precision. `attention_masks` builds both masks in the weights' dtype with `mask_floor(dtype)`; a key the batch padded gets the floor in every row, so padding never changes another text's vector (`granite_tests::padding_does_not_change_a_vector`). The rotary tables are computed in f32 and then cast, since positions past 2,048 are not exact in f16. candle's Accelerate backend has no half-precision matmul, so `modernbert::matmul` runs f16 and bf16 through f32 on macOS: a fallback for the dtype test, never Granite's path (its encoder loads in f32). Attention uses the fused `softmax_last_dim`; the unfused one held four score-sized tensors at once and cost about 100 MB on a batch of chunks.
- `src/tokens.rs`: kitoken does not apply a tokenizer's post-processor template, so `Tokens` reads the template's leading and trailing special tokens from `tokenizer.json` itself and cuts the text's ids before adding them, as `tokenizers` truncates. Special tokens written in the text are matched, as `tokenizers` does. Converting granite's 25 MB `tokenizer.json` costs about 200 MB of RSS that malloc keeps, so `notchling-embed convert-tokens` writes the native file (`tokenizer.notchling`: a magic line, a JSON line with the specials and the pad id, then kitoken's own bytes) and `Granite::load` reads it when it is in the model folder; the fetcher (P7) should write it at download. The parity test checks the native file too.
- `src/granite.rs`: The word table (180,000 by 384) stays bf16 in the memory map and only the rows a batch uses are read; the rest of the weights load as f32. Peak RSS is the gate, so never load the table through the `VarBuilder`. `Granite::embed` runs each text alone, with no padding: score tensors grow with the square of the longest text, and one-by-one is as fast on Accelerate and about 250 MB lighter on a batch of 8 chunks. `embed_padded` keeps the batched path, which the padding test checks against.
- `src/bench.rs`: Reads RSS with `getrusage` and `proc_pid_rusage` (Linux: `/proc/self/statm`), never by starting `ps`. The budget figure runs the chunks in batches of 8 and idles after each batch for the share of time the budget leaves, so it is measured, not multiplied.
- `src/serve.rs`: The daemon's only way in. `serve --model <dir>` prints one ready line, then answers JSON lines `{id, lane, texts}` (1 to 8 texts) with base64 little-endian f32 vectors or an error. Each lane has its own thread: `query` at user-initiated QoS, `index` at background QoS (Linux: `nice 10`), so indexing never slows a search. Accelerate and rayon get one thread (`bench::limit_threads(1)`). It exits after 300 s idle, or once stdin closes and every request is answered.
- `src/convert.rs`: `convert-static` quantizes the static table to i8 per row (512 dimensions), writes it through a fresh `.part` and prints its SHA-256; the daemon stores that as `table-512i8.sha256` and checks it before the table is used.
- `src/part.rs`: Every file the helper writes goes through `create_part` (a stale part removed, `create_new`, no-follow, 0600), then fsync and rename.
- `src/granite.rs::load`: Reads `tokenizer.notchling` (from `convert-tokens`) when it is there, else `tokenizer.json`. A download fetches only `tokenizer.json`, so on users' Macs the JSON path is the one that runs.

## Tests

Tests that need real weights read them from `NOTCHLING_EMBED_MODELS` and are `#[ignore]`; every other test builds tiny weights in memory. Fetch the weights by hand into a folder under `/tmp`, never into the repository (the P4a plan's "Models in development" lists the revisions).
