# Feature map

One row per feature area: where its code is, which tests cover it, and whether a change there may merge on its own. Use it to find what to read before a change.

- **Folders** are named from the repository root.
- **Tests** are named by their path, or sit beside the code (`*_tests.rs`, `tests/`); phone tests are in `apps/flutter/test/`. Fixtures are in each crate's `tests/fixtures/`, except the protocol's, which are in `protocol/fixtures/`.
- **Zone** comes from [`tools/guard/zones.json`](../tools/guard/zones.json), which is the source of truth: `auto` may merge on its own once every check is green, `protected` waits for the maintainer, `mixed` names the files that are `auto`. A new test file is allowed in the zone; a change to an existing test is protected. Check one path with:

  ```sh
  PYTHONPATH=tools/guard python3 -c "from guard.zones import load; print(load('tools/guard/zones.json').in_zone('crates/engine/src/search/rank.rs'))"
  ```

  A file in the zone still goes to the maintainer when it adds a process, pty, network, Keychain, or file write (the capability check), or weakens a test.

Checked against the tree on 2026-11-12. When you add, move or delete a file, update its row.
