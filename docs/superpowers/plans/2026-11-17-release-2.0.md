## T1. Release tool (tools/release/release.py)

Replaces `legacy/macos/release.sh` for the Rust app. `release.py <X.Y.Z> [--dry-run] [--base origin/main] [--date YYYY-MM-DD] [--push] [--open-pr]`.

- Refuses: a version that isn't X.Y.Z, not newer than `[workspace.package] version` in Cargo.toml, a tag `v<X.Y.Z>` that exists, a dirty tree, an existing `release/<v>` branch.
- Writes: Cargo.toml `[workspace.package] version` (bundle-next.sh reads it through `cargo pkgid -p notchling-app`), the matching `version` of every path package in Cargo.lock that had the old workspace version (not `gpui`, which is vendored with its own), `changes/*.md` folded into `## [<v>] - <date>` with the `[Unreleased]` lines through `fragments.fold_text`, and the fragments deleted.
- Real run: `git fetch origin main --tags` (fetch only), `git switch -c release/<v> <base>`, writes, `git commit -m "Notchling <v>"`, prints the next steps. Pushes only with `--push`; opens the pull request (`gh pr create`) only with `--open-pr` (implies `--push`).
- `--dry-run`: no fetch, no branch, no write; prints what it would change (the version lines, the folded section).
- `legacy/macos/release.sh` exits 1 pointing at the new tool.
- Python tests in `tools/release/tests/test_release_tool.py` on a temp git repo: dry run writes nothing, a real run makes the branch and commit with the right files, every refusal, no push without the flag (a fake `git` remote, no network).

## T2. Release workflow (.github/workflows/release.yml)

On a merged `release/<version>` pull request into main. Four jobs, pinned actions as the repo pins them, `permissions: {}` at the top, event fields only through `env:`:

- `gate` (ubuntu, contents: read): checks out the merge commit, reads the version from Cargo.toml, requires the branch to be `release/<that version>`, a `## [<v>]` section in CHANGELOG.md and no tag `v<v>` yet.
- `app` (macos-latest, contents: read, no secrets): `tools/bundle-next.sh` (it sets NOTCHLING_BUILD), checks the bundle's version, makes `Notchling-<v>.dmg` (app plus an Applications link) and `Notchling-<v>.zip`, uploads them with the build id as a job output.
- `nodes` (ubuntu, contents: read): zig and cargo-zigbuild pinned as rust.yml's `node-builds`, `tools/build-node.sh` with `NOTCHLING_DATA_ROOT` in the runner's temp; uploads `notchling-linux-x86_64`, `notchling-linux-aarch64`, `manifest.json`.
- `publish` (ubuntu, contents: write): the manifest's build must equal the app's build; writes `SHA256SUMS` of every asset; notes = the CHANGELOG section plus the install section; `gh release create v<v>` on the merge commit; then the feed: downloads `appcast.xml` from the `appcast` release (or starts one), `appcast.py add --unsigned` with the Stable item (sparkle:version `X*1000000+Y*10000+Z*100+99`, the dmg URL and length, min system 13.0, notes link), `verify`, uploads it (creates the `appcast` prerelease if missing).
- `appcast.py`: `add --unsigned` (no `--ed-signature`), and `verify` accepts an item with no edSignature (one present must still be valid): the Rust app reads only versions and links.
- Beta/promote: left as they are (they need Developer ID and Sparkle secrets and build the Swift app; off while `NOTCHLING_RELEASES` is unset). Ruling.
- Tests in `test_release_workflows.py`: the old-flow test replaced by tests of the new file (jobs, permissions, pins, the build check, no `./build.sh`), appcast tests for `--unsigned`.

## T3. Linux nodes from the release

When the binary step's Fix (Add Machine, Join Cluster, Update N Machines) finds no dist file whose manifest matches this app's build, and this build has a build id and a release version (X.Y.Z), it downloads `manifest.json` from `https://github.com/dtthaison/notchling/releases/download/v<version>/`, requires its build to equal this build and to list the file, downloads the file to a temp name in the dist folder, checks size and SHA-256 against the manifest, renames it into place, then writes the manifest atomically, and continues as today. Anything else keeps today's `tools/build-node.sh` message.

- A `NodeDownloads` trait in the engine (curl through the engine's launcher, `-q`, https only, size cap, timeout) and a fake; no network in tests.
- Probes never download; the probe's message says the Fix downloads it when a download is possible. The update offer counts a downloadable file as Ready, not NeedsBuild.
