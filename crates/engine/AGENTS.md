# engine: notes for agents

## Why the code is this way

The code carries no comments (see [AGENTS.md](../../AGENTS.md)). What a change could break without knowing it, by file:

- `crates/engine/src/accounts/antigravity/login.rs::account`: The older login format (file mirror) has an id_token whose sub is the id; the newer one agy writes names only the email, so it matches a saved account by email. A newer login can't go in the mirror file, so that file is deleted.
- `crates/engine/src/accounts/antigravity/quota.rs::csrf_token`: The CSRF token goes only into a request header and is never stored, logged or returned. The lsof call needs -a, or it lists every TCP listener on the Mac.
- `crates/engine/src/accounts/antigravity/quota.rs::servers`: Limits come from a local language server (Antigravity.app, the IDE, or any agy acp) on a random port; the apps want the CSRF token from their own command line, agy takes none. Skip servers that are signed out or on another account.
- `crates/engine/src/accounts/antigravity/quota.rs::user_status`: The plan name is userTier.name; planInfo.planName is the Codeium plan and always reads Pro. Try the lowest port first: the HTTPS port opens before a plain one just above it.
- `crates/engine/src/accounts/antigravity/store.rs::add_account`: Add Account must delete the Keychain item as well as the mirror file, or Antigravity restores from the item and never shows its sign-in screen.
- `crates/engine/src/accounts/antigravity/store.rs::idle_for_auto_switch`: An automatic switch needs Antigravity closed and no agy running, since a running agy keeps the login it started with and may write it back. Last-read limits are kept in notchling.db because the server answers only while Antigravity is open.
- `crates/engine/src/accounts/antigravity/store.rs::replace guard`: Antigravity's own item is never split and is updated in place to keep its read access. A login too long for one security -i line is refused before anything quits or changes.
- `crates/engine/src/accounts/antigravity/store.rs::switch`: Antigravity's login lives in two places, the Keychain item (service gemini, account antigravity, go-keyring base64) and ~/.gemini/jetski-standalone-oauth-token. A switch must set both, with the apps quit.
- `crates/engine/src/accounts/claude/config.rs::set_oauth_account`: The text is read again just before the write because Claude Code writes ~/.claude.json often. The backup is .claude.json.notchling-backup and both files keep their mode.
- `crates/engine/src/accounts/claude/lanes_side.rs::close_lane`: Before a lane's item is replaced or removed, its claudeAiOauth must match the account's saved slot. Switching or closing a lane first copies the login back, unless the profile endpoint says it belongs to another account.
- `crates/engine/src/accounts/claude/mod.rs::ClaudeAccounts`: One lock covers every operation, Keychain and network included, so a sync can't write back a list read before a removal. snapshot reads a copy so it never waits behind a switch stuck on a Keychain prompt.
- `crates/engine/src/accounts/claude/mod.rs::note_active`: Every place `state.active` is set (`capture`, so a sync and any op that starts with one, and `switch_to` after `activate`) calls it, and it appends the account to `<data dir>/account-log.json` when it differs from the last one logged (`State::logged`, so the file is read once per run and again only after a change or a failed write). The first call after a daemon start also reconciles a login that changed while nothing was running, stamped with the time it is noticed (nothing older is known: the audit log holds no account). It runs under the store's lock but does no Keychain or network call; a failed write is dropped and tried again at the next op, never fails a switch. Claude Code is the only tool the log covers (Desktop's account is in its path, Codex's in the rollout, Antigravity is one account); a lane switch does not change the main login and logs nothing.
- `crates/engine/src/accounts/claude/mod.rs::switch`: Before replacing Claude Code's login, check the live claudeAiOauth reads back from the active account's saved slot. Claude Code renews in place, so the live item may hold the only working refresh token. A failed half-switch is undone through undo_keys.
- `crates/engine/src/accounts/claude/tokens.rs::renew`: Only a saved login that is live nowhere (not main, not in a lane) is ever renewed, rechecked against ~/.claude.json and lanes.json just before the request. The read-only main-token path has no renewal at all.
- `crates/engine/src/accounts/codex/live.rs::write_auth`: auth.json is written under an exclusive flock on Codex's own auth.lock, waiting a bounded time and writing nothing if it can't get it, so a write never lands in the middle of Codex renewing the file. A symlinked auth.json is followed.
- `crates/engine/src/accounts/codex/login.rs::idle_for_auto_switch`: An automatic Codex switch runs only with no codex process (CLI or Chat turn) and the ChatGPT app closed. The managed app server alone doesn't count. An expired Codex token gives no limits until Codex renews it.
- `crates/engine/src/accounts/codex/store.rs::switch`: A switch writes auth.json only once the live login reads back byte for byte from its saved copy. The ChatGPT app quits first and reopens, and the app-server restart sends all output to /dev/null so a daemon holding a pipe can't hang the read.
- `crates/engine/src/accounts/desktop/files.rs::backup`: Cookies.notchling-backup is written once and kept, so it is always the file Notchling found. Account ids become file names only if they are letters, digits and dashes, up to 64.
- `crates/engine/src/accounts/desktop/files.rs::restore`: Claude Desktop's account is decided by claude.ai web session cookies, not the token. Switching copies the whole Cookies file, deletes Chromium's stale write-ahead files, sets lastKnownAccountUuid and bootSideSessions, and only while Desktop is quit.
- `crates/engine/src/accounts/http.rs::LiveHttp`: LiveHttp calls only the two hosts Claude's login uses, and a fixture root gets a client that sends nothing.
- `crates/engine/src/accounts/json_splice.rs::set_top_level`: ~/.claude.json and the Keychain item change by splicing one top-level key in the text, never by parsing and rewriting, so key order, spacing and number spelling stay as Claude Code wrote them. The result is parsed back and checked.
- `crates/engine/src/accounts/keychain.rs::set`: security -i can exit 0 after a command inside it failed, so every write is read back. security -w prints a value with a newline as hex. A value with a control character can't go as quoted text and must go as hex.
- `crates/engine/src/accounts/keychain.rs::text_line`: Items another tool reads (Claude Code's login) too long as hex go as quoted text with backslash and quote escaped. Own saved copies are split by chunked.rs with a sha256 header, and a damaged value is an error, never a wrong login.
- `crates/engine/src/accounts/mod.rs::Secret`: Tokens travel as Secret and Login, whose Debug and Display print no value, so a stray format can't leak one into a log or error. Any HTTP request or response type holding a token hides it in Debug too.
- `crates/engine/src/activity/normalize.rs`: Activity rows are built from three logs by allow-listing fields, never by copying a line: the audit's `reason` is kept (cut to 120 characters) only on a refusal or failure, a result is cut at its first `:` (the vault's `ok:NAME,NAME` must not reach a screen), a phone row keeps its device name and op but never its session id, address or length, and an account switch keeps 8 characters of the id. `list` halves the rows until the JSON is under 900 KB, since the local API's line is 1 MiB. The audit tails are 2 MB each and the first, possibly cut, line of a tail is dropped.
- `crates/engine/src/bridge/connection.rs::Connection`: At most one phone frame is in flight, and a device-window frame offered while another is still going out is dropped, never queued. A second send to a session already running is answered busy.
- `crates/engine/src/bridge/foreign.rs::message_id`: Phone message ids are the first 16 bytes of SHA-256 of a seed from session and item ids, uppercase UUID. They must equal the Swift app's, and stay stable so the hub pushes each message once.
- `crates/engine/src/bridge/foreign.rs::messages`: A last item that may still grow (an Antigravity stream, a tool row gaining calls) is held back until the turn settles, since the hub pushes a message once per id. Antigravity permission ids are agy-perm:<row>:<rpc>, and the rpc id may hold colons.
- `crates/engine/src/bridge/images.rs::to_jpeg`: Chat pictures are flattened onto white because JPEG has no transparency (else screenshots turn black), clamped to 16..1600 px, and refused by header before decoding when they claim too many pixels.
- `crates/engine/src/bridge/mod.rs::Router`: Requests are read field by field: a field of the wrong type counts as absent, as Swift did, and any JSON id is echoed back. Answers have sorted keys and whole numbers without a fraction. The phone's wire format is byte-compared with protocol/fixtures/.
- `crates/engine/src/bridge/net/access.rs::TunnelAccess`: Tunnel traffic arrives from loopback via cloudflared, so Cloudflare's headers are the only way to tell it from a local client. The pairing QR keeps v at 1 and every v1 field so an older phone ignores tunnel. The client secret stays in access.json.
- `crates/engine/src/bridge/net/address.rs::is_allowed`: Only loopback, 10/8, 172.16/12, 192.168/16, link-local and Tailscale (100.64/10, fc00::/7) may open a connection. An IPv4-mapped IPv6 peer counts as its IPv4 address for the limiter and audit log.
- `crates/engine/src/bridge/net/bridge.rs::halt`: Bridge-off first halts AuditLog and DeviceStore, which check a flag under their lock before each write, so nothing in flight (a hello, a pair, a revoke) writes after the switch goes off. Off binds no port, and a busy port is an error, never another port.
- `crates/engine/src/bridge/net/devices.rs::DeviceStore`: devices.json is byte-identical to Swift's JSONEncoder output (slash escaped) so either app reads it. Only token SHA-256 hashes are stored and compared in constant time over every device. lastSeen is written at most once a minute and a file in another format is never overwritten.
- `crates/engine/src/bridge/net/fetch.rs::fetch`: The Access-key fetch runs the name lookup on its own thread because the system resolver has no timeout. It runs only for a request carrying Cloudflare headers while internet access is on, and treats close without close_notify as a complete answer.
- `crates/engine/src/bridge/net/files.rs::sorted`: Bridge files in the Swift format need sorted keys written explicitly, because serde_json keeps insertion order once another crate turns on preserve_order. Dates are whole-second UTC iso8601, the only form Foundation reads.
- `crates/engine/src/bridge/net/frame.rs::decode`: The 256 KB message cap is enforced on the frame header, so a too-big frame is never buffered (close 1009). Clients must mask, and a request head too big or too slow gets a real HTTP status and is dropped.
- `crates/engine/src/bridge/net/identity.rs::BridgeIdentity`: The LAN certificate is read byte for byte from the Swift app's `identity.p12` and `identity.pass` (the Swift app deletes `key.pem`) so a paired phone's pinned fingerprint still matches; the bridge never makes or replaces one.
- `crates/engine/src/bridge/net/identity.rs::server config`: The certificate is served unparsed because macOS LibreSSL makes X.509 v1 and rustls's webpki check refuses v1; the phone pins the fingerprint, so don't add certificate validation.
- `crates/engine/src/bridge/net/jwt.rs::AccessJWT`: The Access key cache fails closed: a failed fetch serves cached keys only while under an hour old, an unknown `kid` refetches at most every 30 s, and the fetch runs without the lock.
- `crates/engine/src/bridge/net/limiter.rs::AuthRateLimiter`: Tunnel clients are keyed by `Cf-Connecting-Ip`, never by cloudflared's loopback address, and an IPv6 address counts as its /64, so a host can't dodge the backoff by changing addresses.
- `crates/engine/src/bridge/net/server.rs::BridgeServer`: A phone sends `hello` or `pair` within 10 s (pings don't count) and finishes the head within 5 s; one LAN address holds at most four unauthenticated sockets; pushes never wait on a slow phone, whose bounded queue marks it dropped.
- `crates/engine/src/bridge/net/server.rs::handlers`: Each text frame runs on its own thread (a `pair` blocks on the person, a reply on the terminal) with a per-phone cap; an accepted socket inherits non-blocking mode on macOS and must be reset.
- `crates/engine/src/bridge/net/wire.rs::Wire`: TLS reads take the lock only to feed rustls, and a read returns `Interrupted` when no plaintext has arrived so the caller rechecks its deadline; `shutdown` never waits, and writes go in pieces under rustls's 64 KB limit.
- `crates/engine/src/bridge/router.rs::interrupt`: Interrupts are limited to one per session per three seconds, since a second Esc would cancel the queued message.
- `crates/engine/src/bridge/router_ops.rs::photo and web ops`: A photo reaches a session only through the backend's acting call, so with acting off nothing is taken in; `web.snapshot` accepts only http(s) on localhost or 127.0.0.1 and gives the renderer the re-serialized URL without user info.
- `crates/engine/src/bridge/uploads.rs::PhoneImageStore`: Photos are saved as `phone-<8 hex>.<ext>` mode 0600 in a 0700 folder, named here and never by the phone, with the extension from magic bytes; an upload expires so trickling pieces can't keep it alive.
- `crates/engine/src/bridge/wire.rs::encode`: Text frames are JSON with sorted keys, unescaped slashes and whole floats written as integers, as the Swift bridge wrote them; binary frames are `PHN1`, `IMG1` and `WEB1` magic plus a big-endian u32.
- `crates/engine/src/catalog/claude_code.rs`: Claude Code's `additionalModelOptionsCache` in `~/.claude.json` is read only and never written; it is the fallback list when the live fetch fails.
- `crates/engine/src/catalog/claude_live.rs`: The live Claude list (`GET /v1/models`) only names models; the context window stays the data file's because the API's `max_input_tokens` differs. Errors name status or shape only, never the body or token.
- `crates/engine/src/catalog/claude_live.rs::refusal`: A 400, 403 or 404 from the models endpoint means it won't serve this login, so do not ask again with the same token (kept as a SHA-256 fingerprint); 401 and 429 pass with time and are retried.
- `crates/engine/src/catalog/live_cache.rs::put`: One process-wide lock covers the whole read-modify-write because several `LiveCache`s share the file; writes go to a uniquely named temp file then rename, and an older-than-a-day or clock-skewed entry counts as stale.
- `crates/engine/src/catalog/mod.rs::Catalog::load`: A user override file can fix a price, window or name but never adds a model to the allowlist; only built-in lists and what the tool reports live can.
- `crates/engine/src/catalog/mod.rs::borrowed price`: A Claude id newer than every known one in its family is priced and sized as the newest known one (`borrowed`), unless an entry made for that id says otherwise; a model with no price is unpriced, never $0.
- `crates/engine/src/catalog/mod.rs::price matching`: Claude prices match by id prefix, first match wins, so the longest prefix sorts first; a match must end on a `-` segment boundary (`fable-5-1` is not `fable-5-10`). Other tools match the whole id.
- `crates/engine/src/catalog/mod.rs::prices_hash`: The cost cache is repriced against the fingerprint of all price entries after the override merge; windows, names and model lists are not in it, so changing only those never reprices.
- `crates/engine/src/catalog/mod.rs::startable_shape`: A Claude model id goes onto a command line, so it must match lowercase ASCII plus an optional `[1m]` only; `model_key` cuts at the first `[`, so `claude-opus-5-5[1m] --flag` would otherwise pass.
- `crates/engine/src/control/git.rs`: Every git call uses `--no-optional-locks` so the inspector never takes the index lock the session's own git needs; only stdout is read.
- `crates/engine/src/control/launcher.rs::RealLauncher`: Child output goes to a temp file, not a pipe: the first `claude --bg` in a lane starts a host that inherits the pipe, so reading to EOF would wait as long as that host lives. `NO_COLOR` is dropped (it grays Claude Code's menus).
- `crates/engine/src/control/launcher.rs::output files`: Output files are created 0600 with `O_EXCL|O_NOFOLLOW` under random names (they hold job names, prompts, paths), read back through the same handles after rewinding the shared offset, and removed even on timeout.
- `crates/engine/src/control/plan.rs::Command env`: A main-login command removes `CLAUDE_CONFIG_DIR` rather than inheriting it, so a daemon started from a lane never runs, or trusts a folder, in that lane.
- `crates/engine/src/control/run.rs::parse job id`: The new job id is read from `claude --bg` output (`backgrounded · <8 hex> · name` before 2.1.318, `backgrounded · <8 hex> (idle ...)` after, maybe after a note line); "Workspace not trusted" means plan again with trust.
- `crates/engine/src/control/session.rs::STOP_SETTLE_MS`: After `claude stop` the host needs a pause before the transcript is released; a Move must wait it out before `claude --bg --resume`, and must read the job's `respawnFlags` before the stop.
- `crates/engine/src/control/session.rs::plan_move trust`: Each account keeps its own trusted folders (`<lane>/.claude.json`, or `~/.claude.json` for the main login, `claude_json_for`), so a resume in an account that never trusted the session's folder fails with "Workspace not trusted". The daemon (`control_ops.rs::needs_trust`) checks the target's file for the folder or a parent and, if it isn't trusted, the plan runs the trust script under the target first. That step comes before the stop, so a refused trust leaves the session running. The root and the home folder are never trusted this way.
- `crates/engine/src/control/session.rs::plan_remove`: `claude rm` runs in every folder holding a copy of the job (a moved session leaves a stopped copy); only the current copy's result counts and a failure there must not stop the stale copies being removed.
- `crates/engine/src/control/slash.rs::MENU_COMMANDS`: Commands that open a menu write nothing to the transcript and a hidden attach shows nothing, so Chat runs them in a terminal; the built-in list comes from `slash_commands` of 2.1.318 and needs updating when Claude Code adds commands.
- `crates/engine/src/control/takeover.rs`: Takeover checks run in order and a still-running original is `Alive` before anything else (two writers corrupt a session); session ids must be UUIDs before they reach a path; every `CLAUDE_CODE_*` variable is dropped from the spawn environment.
- `crates/engine/src/control/trust.rs`: The trust prompt lists "No, exit" first and selected (2.1.318), so accepting is Down then Enter, then Ctrl+C twice after the session screen appears; no `NO_COLOR`.
- `crates/engine/src/control/wake.rs`: After a wake only background jobs whose last reply ended in the "computer went to sleep" error are nudged, once per cut-off, after a settle delay and within a window; terminal and `claude -p` sessions are never nudged.
- `crates/engine/src/cost/account_log.rs`: The CLI's transcripts carry no account, so cost goes to the account active at message time from `account-log.json` in the data folder; `at` is seconds since 2001-01-01 (or an ISO 8601 string on read). The Swift app wrote it and, since it was retired (2026-11-11), `ClaudeAccounts::note_active` does, through `record`: `plan_record` is the pure part and splices one `{"at":…,"id":…}` after the file's last entry so the old bytes stay as they were, `Unchanged` when the latest entry already names the account, and `Unreadable` for a file that isn't a JSON list, which `record` never writes over. One process-wide lock covers the read and the write (`write_private_no_follow`, atomic, refuses a planted link). There is no size bound, as in the Swift app: an entry is added only when the account changes.
- `crates/engine/src/cost/cache.rs`: The cost cache is the `CACHE_DOC` row of `notchling.db`, never the Swift app's `cost-cache.json`. Changing stored fields means bumping `CURRENT` and migrating the old version in `load`, since transcripts of old days are gone.
- `crates/engine/src/cost/other.rs`: Codex `input_tokens` includes cached tokens and `output_tokens` includes reasoning; only `last_token_usage` is counted. Antigravity steps carry no model, so it is the last "Model Selection" setting change in a `USER_INPUT` step.
- `crates/engine/src/cost/paths.rs::transcript_name`: A transcript is identified by the last four path parts, so a symlinked temp folder (`/var` vs `/private/var`) does not count the same file twice.
- `crates/engine/src/cost/tracker.rs`: Messages are counted once by `message.id|requestId` hashed with FNV-1a (Claude Code copies messages into new transcripts on compaction or resume); Codex repeats events, so an event with the same `total_token_usage` is dropped.
- `crates/engine/src/cost/tracker.rs::reprice`: A changed price reprices only that model: transcripts still on disk are recounted exactly, and days whose transcripts are gone are rescaled from the cached tokens, so never drop a day or recount other models.
- `crates/engine/src/delegate/agy_run.rs`: agy's `initialize` offers no fs or terminal, so other agent calls get -32601; permission requests are declined and listed except workspace edits with `--write`; the reply is the text after the last tool call, excluding the `session/load` replay.
- `crates/engine/src/delegate/agy_trust.rs`: Before `agy acp` starts, a folder Claude Code trusts is added to `trustedWorkspaces` in agy's settings.json (both the given and real path); never remove entries, and leave the file untouched if it is not a JSON object or the list is not a list.
- `crates/engine/src/delegate/codex_run.rs::watcher`: Stop escalates SIGINT, then SIGTERM, then SIGKILL, each after `terminate_after`, so `--timeout` holds for a turn that traps signals; one argument over 128 KB is refused by Linux execve.
- `crates/engine/src/delegate/media.rs`: Session ids and `--out` come from outside, so an id must be one plain folder name, only regular files directly in the session folder are taken, and a symlink (folder or file) is never followed or copied.
- `crates/engine/src/delegate/options.rs::depth`: Nested delegation stops at depth 2 via `NOTCHLING_DELEGATE_DEPTH`, so two agents cannot hand a job back and forth; the command needs no daemon and is not behind the `acting` switch.
- `crates/engine/src/delegate/progress.rs`: agy's image subagent outlives the turn and the parent's answer goes only to the transcript, so closing agy early kills it; wait on file events until every subagent this run started reported, with a periodic recheck so a missed event is a delay, not a hang.
- `crates/engine/src/delegate/record.rs`: A delegation record is written only when `CLAUDE_CODE_SESSION_ID` is set, atomically 0600, and a write failure never fails the job; a record with no `ended` whose pid is gone or older than a limit counts as stopped (pids are reused).
- `crates/engine/src/delegate/second_opinion_host.rs`: Stop is SIGTERM then SIGKILL after a grace; on app quit `stop_within` waits and kills in place because a helper thread would die with the app first.
- `crates/engine/src/docfile.rs::DocFile`: The old file is moved into its row once and a row already there wins; a link, an unreadable file or one `valid` rejects stays put and is never written over, and reads never make the database.
- `crates/engine/src/git/guard.rs`: A path from a client is checked before any command runs: relative, no `..`, no NUL, and walked component by component so a link that leaves the repository (or dangles) is refused; the folder must be a known session's or below one after `canonicalize`, so a link out of a session folder is not below it.
- `crates/engine/src/git/sandbox.rs`: `SandboxedLauncher` wraps every git read in `/usr/bin/sandbox-exec` with a profile that allows everything except `process-exec*` and then allows exec of git's own binaries only, and only binaries that a user cannot swap for a copied shell: the candidates are the target `xcrun --find git` names and `/Library/Developer/CommandLineTools/usr/bin/git`, and one is allowed (with its `../libexec/git-core`) only if its canonical path and every parent up to `/` is owned by root and not writable by group or others (`root_owned_chain`, pure over an `Owner` lookup so a test can feed it user-owned and group-writable folders). The first allowed one is exec'd directly, not through the `/usr/bin/git` shim. Homebrew's git is never allowed (its Cellar is user-owned), and an Xcode.app under `/Applications` never passes either, since `/Applications` is group-writable by `admin`: the Command Line Tools are what runs. With no allowed git the read is `can't read this repo safely`. Resolution (`xcrun`, the ownership walk) starts when the launcher is built, on a background thread; a call that arrives before it ends waits 1 s and answers `still starting`, and a failed resolution is tried again at most once a minute on a later call, so a Command Line Tools install made after the daemon started is picked up. Why: the `-c` nulling in `read.rs` re-reads the config in every run, so an agent that rewrites `.git/config` (or an included file) in a loop can add a `[filter "evil"]` between the `config` read and the `diff`; the kernel stops a filter's `sh -c`, a hook, fsmonitor, textconv or a process filter whatever any config says, so the content of the config no longer matters. The nulling and the flags stay as defence in depth. Never fall back to an unsandboxed run: a missing `sandbox-exec`, a profile it refuses (exit 71 `sandbox-exec:`), or a program other than `git` is `can't read this repo safely`, and off macOS `run` is `LaunchError::Unsupported` (`Failure::Unsupported`, the op answers `unimplemented`). A filter that now fails to start makes git print an error and treat the file as changed; accepted, so LFS files with a changed timestamp may show as modified with a binary diff. `sandbox_tests.rs` runs plain git (no nulling, no `--no-optional-locks`) through the sandbox against real traps (clean, process, shell filter, hook, fsmonitor, textconv), each proved to fire without it first.
- `crates/engine/src/git/branch.rs`, `branch_file.rs`, `branch_parse.rs`: The branch comparison for the Changes panel (`read_branch_stat`, `read_branch_diff`, `read_branches`), over the same `command`/`run`/`drivers` as `read.rs`, so the same read-only flags, sandbox and timeouts apply; nothing here may run a git subcommand that writes. It diffs the working tree against `merge-base <base> HEAD` (`diff --name-status|--numstat -z -M <sha> --`), so it covers the branch's commits and uncommitted work in one list, and marks which files differ from HEAD (from `status`) so the answer can say it includes uncommitted work. The base is validated by `guard::clean_ref` (plain branch characters only, no leading `-`, no `..`) before anything runs, because it reaches git as an argument; an unknown base is `failed`, never a run with a guessed one. A repository with no commit, or with none of origin/HEAD, `main`, `master` sharing history with HEAD, answers with no base and no files, not an error, since the app asks every 5 s. Untracked files have no numstat, so their lines are counted by reading them (a symlink, a binary, a file over 2 MB or the 8 MB budget gives `null`). A rename is one `R` row with `from`; its patch needs `from` too, or it shows as a new file. Files are cut at 2,000 and the totals count all of them. `read_diff` shares `untracked_diff` and `patch` with `branch_file.rs`.
- `crates/engine/src/git/read.rs`: Every command is read only and bounded, and runs no program of the repository, since the daemon asks every 5 s with nobody clicking: `--no-optional-locks` (no index write, so no `post-index-change` hook), `core.fsmonitor=false`, `core.hooksPath=/dev/null`, `diff.external=`, `--no-ext-diff --no-textconv`, `--ignore-submodules=all`, and each filter driver named by `config -z --get-regexp ^filter\.` (which runs nothing) gets `clean=`, `smudge=`, `process=` empty and `required=false`; a driver name git's `-c` can't carry (`=`) refuses the read. Every inherited `GIT_*` variable is cleared and `LC_ALL=C`, `GIT_TERMINAL_PROMPT=0`, `GIT_PAGER=cat`, 3 s. `Launcher::run_capped` stops a command that writes past 4 MB (lists) or 128 KB + 1 (a diff); the real one watches the output file's size, the default (fakes) cuts after. `read_hardening_tests.rs` runs real repositories with a trap for each (clean, process, textconv, external diff, `post-index-change`, fsmonitor) and first checks the trap fires with plain `git`, so a test that proves nothing fails. Not a repository is `rev-parse --is-inside-work-tree` after a 128, never the message. `read_diff` answers only a path that is exactly one of the status entries. - `crates/engine/src/tools/codex/runs.rs::CodexRuns`: The acting check runs under the state lock before spawn and again once the process exists, Started is sent before the turn's Ended, and the next queued message is taken under one lock with the slot release.
- `crates/engine/src/transcript/chat/images.rs::read_file`: A path a message names is shown only if it resolves under the home folder or /tmp, and is checked again at read time: opened without following links, judged by the handle, FIFOs refused, size capped.

- `crates/engine/src/transcript/continued.rs::earlier`: Claude Code moves a running session into a new session id (sending it to the background), leaving a `continued-in` record in the old transcript and, at first, only a title and a name in the new one; `earlier` finds the old files in the same project folder from that record in the last 16 KB (it sits within 2 KB of the end), ignores a record whose `sessionId` is missing or not the file's own (a copied line), and stops at 8 sessions or a loop. - `crates/engine/src/transcript/conversation/join.rs::read`: Once the new session gets going, Claude Code copies the old messages into it (with `sessionId` rewritten), so `conversation::read_shared` and `snapshot::read` join earlier sessions only while the new one has no User or Assistant item (no lines for the snapshot); a chain follows back through empty sessions and stops at the first earlier one that has messages. Joining anything else showed the history twice and double-counted turns and tokens, and left a gap once the new transcript passed the 4 MB tail. A join puts the earlier items first (ids prefixed with their session id so rows stay unique, tool calls marked finished since nothing runs there, at most 1000), sums tokens and turns, takes the model and branch from the newest earlier session that has one, and caches by the `Arc`s it joined, so an unchanged file is still the same `Arc`.
