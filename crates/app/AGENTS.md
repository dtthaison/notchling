# app: notes for agents

## Why the code is this way

The code carries no comments (see [AGENTS.md](../../AGENTS.md)). What a change could break without knowing it, by file:

- `chat/codex_children.rs::DaemonChildren`: Asks the daemon's `codex.children`; after a failure it skips the daemon for 30 s and falls back to `DayFolders` (two day folders), so a missing daemon costs one failed call, not one per load. The registry asks once per delegated Codex job and per Codex child, so the asks go over one connection (`Kept`) that the loader closes when the walk ends (`ChildSource::done`): a new connection costs about 28 ms (connect, hello, the peer checks), a call on an open one about 0.04 ms, and a connection per ask made a session with 289 delegated jobs take 9 s a load. A connection whose call failed is dropped, never reused.
- `chat/paging.rs::Tree`: Rows come from the registry in depth-first order with `parent`; a group's `Page` is made when it is first opened and kept until the session changes. A new field a row shows goes in `SubagentRow`, never read from `ChatView` in a draw.
- `chat/activity.rs::stalled_prompt`: A request Claude Code sent on a connection that died while the Mac slept waits with no error; sending the prompt again starts a fresh one (Retry after `STALL_S`).
- `chat/activity.rs::working`: A session whose state is not working shows no live line whatever a stale transcript says, and a turn that ended while the session still works means a background command.
- `chat/claude_picker.rs::Choice`: A model or effort pick is an ordinary reply (`/model <full id>`, `/effort <level>`) with an argument, so the engine types it in; the bare command would open a terminal (`slash::route`).
- `chat/claude_picker.rs::hint`: A pick stands in for the transcript only while the transcript still says what it said at pick time, and for 30 s at most.
- `chat/cleared.rs::read_with_model`: A /clear in a background job starts a transcript that names no model; the model and effort come from the transcript the clear ended (`locate::predecessor`), and the same inputs must give the same `Arc` back. The Details Panel lists the subagents of those earlier transcripts too (`cleared::subagents` is the engine's `subagents::list_across_clears`, reached through `ClaudeSubagents::list` and so `Registry::subagents`: up to `MAX_BACK` transcripts, nearest first), because Claude Code leaves a subagent under the folder it ran in, finished or not. A subagent that was running at the clear continues in a new file in the new folder, under the same id and without a `meta.json`: it is listed once, as the newer file (what opening it reads), with the description, type and model of the older folder's `meta.json` (`subagents::list_chain`). Only that newer half is shown; the older half of its history is a known limit. A completion notification can land in any later transcript, so every earlier call judges its folder by the `finished_agents` of the whole chain plus the current conversation, as `join.rs` does for `continued-in`. The earlier transcripts are never read through `conversation::read_shared`: `engine::transcript::finished::read` scans a bounded tail for the lines that end an agent and is cached by file size and mtime.
- `chat/composer.rs::menu_for`: Codex turns are `codex exec`, which has no slash commands, so its + menu has no Slash Commands row.
- `chat/data.rs::DataRoot (render)`: A render or fixture root never reads the real `~/.claude`; its rows never age out of Done and its Codex files are not date-filtered.
- `chat/data.rs::Tool::name`: It is matched against the `tool` field of the daemon's rows (`sheets/client_model.rs`), so it returns `markers::TOOL_*` and never changes with the language; the name to show is `Tool::title`, a message.
- `chat/data.rs::dedup of watched folders`: A lane's `projects` is a symlink to the main one, so config folders are deduplicated before scanning; each folder is watched once or the poll scans it twice.
- `chat/data.rs::own_dir`: The app's own data folder is apart from the Swift app's files and the daemon's `daemon/`: Swift copies over `data/antigravity` and keeps writing beside this app.
- `chat/delegated.rs::parents`: Delegated jobs are matched to a session by Claude Code's session id (the transcript file stem), and the transcripts its clears ended count too, so jobs stay with the row you see.
- `chat/drops.rs::local_target`: Agents link files relative to the session folder (Codex `<out/a.png>`), and macOS Finder fails with error -50 on a bare relative path, so links are resolved against the folder first.
- `chat/drops.rs::passing`: A screenshot thumbnail drop is a file macOS deletes soon (`TemporaryItems/NSIRD_screencaptureui_`); it is copied into `store/<now_ms>/` first so the session can still read it.
- `chat/file_panel.rs::read`: The file stamp is taken before reading so a write during the read shows as a change on the next look; reads are capped at `MAX_TEXT` and cut on a character boundary.
- `chat/git.rs::Gate`: The Details Panel's Git status is asked of the daemon, never run by the app, and never from a draw: one call at a time, a new folder or the panel opening at once, a turn that ended after 1 s since the last, and the tick (every 0.5 s) only after 5 s, and only while the Details Panel is on screen (not under the page or file panel, the terminal, the simulator, or hidden). A fixture or render root makes no call. The result goes into `DetailsModel` as an `Arc<GitModel>` and `view/repo.rs` drops an unchanged one before asking the part to redraw.
- `chat/history.rs::apply`: The choice strings (`2mb`..`16mb`) are the settings key's allowed values; an unknown or missing value is 4 MB, never an error. It runs once, in `mac/shell.rs::run` before any window opens, and opens the settings store, so it never runs from a load or a draw; a read that fails (`read` is `None`) keeps the current number. The Settings sheet's own change goes through `history::on_change`, called from the `SettingChanged` event `ChatView::open_settings` subscribes to, and asks for one reload only when the number changed.
- `chat/html_preview.rs::Untrusted`: A local `.html` file (opened from a link, a path in a message, or a Git row) is not a saved Artifact: an agent wrote it and may have been told what to put in it. It opens in the page panel's `wry` web view as `PanelPage::Untrusted`: JavaScript off (`with_javascript_disabled`), a non-persistent data store, navigation only inside the file's own folder (`stays_local`), no new windows, read access (`loadFileURL_allowingReadAccessToURL`) to the file's folder alone, and no IPC handler or custom protocol, so nothing reaches the bridge or the local API. Relative CSS and pictures load; remote images and styles still do (WebKit doesn't ask the navigation handler about subresources), which gives the page nothing the agent that wrote it did not already know, since no script can read or send a thing. Open in Default App is the way to run its scripts, in the user's browser. The subtitle says "Scripts off". Don't enable scripts, an IPC handler or a wider read folder here without a decision.
- `chat/html_preview.rs::git_look`: A Git row of an `.html` file keeps showing its diff, except for a new file (`?`, `A`): its diff is only its source, so it opens as the page (Show Changes is the toggle back). The page is found from the repository root (`repo_root`: the nearest ancestor of the session folder with a `.git`, file or folder), because Git's paths are relative to the root and not to the session folder, and a deleted file offers no page. The lookup is `Path::is_file` on the click, never in a model or a draw; a path with `..` or an absolute one finds nothing.
- `chat/inspector.rs::fact_text`: A plural message prints its selector through the language's number format, so 1200 would read 1,200; a message whose English must keep 1200 (`chat-details-turns`, `chat-details-commands`, `chat-changes-file-count`) takes the number again as a string. The step, image, shell and queue counts (`chat-steps-*`, `chat-images`, `chat-shells-running`, `chat-messages-wait`) do not, and read grouped from a thousand.
- `chat/markers.rs`: Text matched against another program's screen or output, and labels that are keys: the dialog markers of `prompt_flow.rs` and `prompts.rs`, Claude Code's past-tense step words, the tool names, the Details Panel's fact labels and the `/model` and `/effort` commands. The file is in no area of `tools/locale/areas.json` on purpose, so nothing here is flagged or translated; `reply_words_tests::markers_stay_literal` holds that no marker equals an English message. A new matched string goes here, never into `chat.ftl`.
- `chat/paging.rs::Page`: What the Details Panel lists is state, not a function of the list: shown ids only grow (a running one that finishes stays, a new one goes first), the first page is decided once per session, and `show` is called by the loader on every load, so a click's `more` is consumed exactly once.
- `chat/shell_list.rs::probe_paths`: The probe's argument list is the shown, unfinished shells' output paths, each once and in display order; the model asks `writers` about the same set (a test holds it), so a shell that is not shown is never probed, with one exception: while the listing is `waiting` (no answer yet for every unfinished shell) the probe asks about all unfinished shells with no answer, and the page is made when they have one. A shell the probe found with no writer is ended for paging and leaves the probe. `ChatView::refresh_shells` runs in `apply` and after an Antigravity read; it is pure, so it may run on the main thread.
- `chat/subagent_rows.rs::SubagentRows`: Rows are built only for shown subagents and read at most once per file stamp (size and mtime); it takes no part in `Cursors`, whose 30-file LRU would thrash.
- `chat/branch.rs`, `chat/branch_rows.rs`, `chat/view/changes.rs`, `chat/view/changes_panel.rs`: The Changes panel's models and views (docs/notes/chat-details.md, Changes). `branch.rs` is pure: the reply parsers (a reply with no `base` is no model), `LARGE_LINES` (2,000 changed lines) and `LARGE_FILES` (100) for the Large diff badge, the path filter (every word of the query anywhere in the path, any case) and the three requests. `branch_rows.rs` is pure: the flat row list of the shown files with their open diffs, the smallest splice between two lists, and which open files a new stat makes ask again. Nothing in the panel's draw reads a file or the socket; every daemon call is made from `ChatView` off the UI thread (`view/changes.rs`) and its answer is pushed into the panel, dropped if the base has changed since it was asked.
- `chat/worktrees.rs`, `chat/view/worktrees_ask.rs`, `chat/git_gates.rs` (docs/notes/chat-details.md, Git section): `worktrees.rs` is data in, rows out: it reads no file and starts no process, and a compute that formats a message with variables does it there, never in a draw. Which session or subagent is in a worktree is matched here, in the model compute, from the live session list and the selected session's subagent rows (`owner`: the longest component-wise prefix of a folder among each worktree's `path` and `real`; a session's folder is `worktreePath` when set, else `cwd`), so "running" is never older than the Sidebar; the daemon only gives the paths. A session that ran EnterWorktree is "this session" in its worktree and appears once. The Git section's call has its own `SlowGate` (15 s tick, 1 s floor on events, one call in flight, a retry after `PENDING_AGAIN_MS` while rows are pending), and so does the Branches feed, so opening Branches never waits on a Details call. The `fresh` paths are the worktrees whose occupancy kind changed (`fresh_after`: only paths present before and after, at most two; a new worktree is not fresh, since the daemon reads a worktree with no work first anyway). The ask after a session list change runs from `apply`, after the sessions and subagent rows are stored: asked from the tick it compared the old rows, and the 1 s floor then swallowed the ask that should have followed. A failed call keeps the last good rows. Ages are computed from a clock rounded down to the minute and under a minute read "just now", so a running clock never redraws the part. The "›" row has four forms; `chat-git-default-and` and `chat-git-more-worktrees` wrap their whole text in the select, since `GUARD-LOCALE-SUBSET` needs a select to be the whole value.
- `chat/changes_target.rs`, `chat/view/changes.rs`, `chat/view/repo.rs`: Two states, not one. The session's own `BranchModel` and `base_choice` live in `repo::State` and keep feeding the Git section; Changes on another worktree or branch has its own `TargetState` (`repo::State::other`), cleared when Changes closes or the folder changes. If both shared a field, closing Changes would show another branch's numbers and base on "this session". The own stat is asked with `pick: "nearest"` unless a base was chosen, so the Git row and Changes agree on the base; a base the daemon refuses falls back to the nearest one, and a target it refuses stops asking until Changes closes.
- `chat/branch_list.rs`, `chat/branches_state.rs`, `chat/view/branches.rs`, `chat/view/branches_panel.rs` (docs/notes/chat-details.md, Branches): The tabs are views over one list (`in_tab`), not a partition, so a worktree can be in Working and in Not Merged; the bases are never in Not Merged or Merged, and a worktree is Merged only once its work was read and is clean. `Feed` holds one folder's list, a gate and a generation: a hidden session switch forgets the feed and bumps the generation, a reply of an older generation is `Stale` and never touches the gate (a late reply used to clear a reset gate's in-flight flag and let two calls run), and `list_for` and `failed_for` give nothing for another folder, so another repository never shows the old list. `Shown::set_input` keeps the last list when an error follows a good reply. A branch name `clean_ref` refuses is listed but its Changes button is off, as is a missing folder's; Open Session needs a matched session or subagent. Hide Details closes the file panel, then Changes, then Branches (`hide_step`), and Changes opened from Branches goes back to it (`after_close_changes`).
- `chat/view/page_panel.rs::html look`: `Shown::html` (an `HtmlView`) holds an HTML file's page-or-source choice; the header's two buttons (Page, and Source or Changes) call `set_html_look`. Page look is the web view (`PanelWeb`, hidden under the same covers as a saved page); Source look drops the web view and shows the file panel's text (`FileState`) or, for a Git row, the diff the row already fetches. The tick reloads the page when the file's size or time changes (`HtmlView::moved`, one `metadata` call, as `refresh_file` already does for text) and shows "This file is gone." when it is gone. `NOTCHLING_RENDER_FILE=<file.html>` renders the chrome; add `NOTCHLING_RENDER_HTML=web` for a real web view in the capture (WebKit needs more than the render's 0.9 s to load, so also `NOTCHLING_RENDER_BENCH=3 NOTCHLING_RENDER_BENCH_MODE=idle`, which keeps the window up; `tests/render_html_preview.rs` does this and checks the page's colors, that its picture and style beside it loaded, and that its script did not run) or `source` for the text look.
- `chat/view/diff_panel.rs`: A file's diff opens in the file panel's frame as `Opens::Diff` with `Shown::diff`; its lines are told apart only after the first `@@` (a removed line that begins `-- ` is not a header), and added and removed lines use the `Done` and `Expired` inks. Its lines are chunked once, in `set_diff`, never in a draw, and a reply equal to the one shown changes nothing. An open diff is asked again on the tick every 5 s (`git::diff_due`), even while the page panel hides the Details Panel, and keeps the old text on screen until the new arrives; selecting another session closes it, and a status reply for a folder that is no longer selected is dropped (the current folder is then asked at once).
- `chat/inspector.rs::shells`: Shell running state needs a live process asking `writers` (a process holds the output file open); a reader without it shows a shell with no notification as ended.
- `chat/loader.rs::Loader`: The change between loads is computed off the main thread; the view only checks that the change starts from the conversation on show, and Antigravity's log is re-read only when its size or date changes. Chat's loader is `quick_on_switch`: the first load of a session other than the last one loaded is `partial` (sessions, conversation, question; no subagent list, rows or children asked), and `apply` starts the full load at once, so a switch shows the conversation without waiting on the Details Panel's subagents. A partial load consumes no `Load More` and does not count against a pending child's loads. A test or tool that wants every load whole uses `Loader::new` alone.
- `chat/log.rs::diff`: The engine numbers items by line and keeps the newest few hundred, so a change is only a trimmed front, a grown end or an in-place edit; any other shape (ids not lining up) resets.
- `chat/view/outbox_rows.rs`, `chat/outbox.rs`, `chat/view/tools.rs::dispatch`: Chat sends to an existing Claude Code, Codex or Antigravity session with `session.send` (`outbox_rows::send_request`, remote rows too: the qualified id forwards to the owner node, whose Outbox keeps the mailbox; drafts keep `codex.send`/`agy.send`), which answers in milliseconds with the row saved in the daemon's Outbox. The reply box and attachments clear at once and the message shows as a Queued bubble (an `Outgoing` entry drawn as `Row::User { outbox: Some(Bubble) }`) until the `outbox` topic's row arrives; `outbox::unbubbled` then hides the entry one for one so there is one bubble. A send that came back with an `outboxId` ties its `Outgoing` to that row (`outbox::deliver`), and `sync_tools` drops the entry, in every session's list (`outbox::drop_covered`), as soon as the feed shows the row (`OutboxFeed::shows`, also while it is a Sent bubble) or has seen it removed (`OutboxFeed::covers`: the last 200 removed ids, noted even when the removal arrives before any change for the row, so a row removed on the notch or phone while another session was selected leaves no ghost bubble; a `sent` removal of a row never shown is not noted, its entry waits for the transcript), and Remove, Drop and a finished edit drop it too (`outbox::forget`), so an edited or removed row leaves no second Queued bubble behind. Rows sit in queue order per session whatever order they arrive in (the follower daemon republishes remote rows as it lists them, and a second client's list may differ): a new row goes before the first one with a later `queuedMs`, then `position` (`OutboxFeed::seed` and `upsert`), and an update keeps its place, so the first bubble and `needs_you` are the head. A row that comes back after it was sent (Send Again) drops its entry from the feed's sent list (`prune_sent`, on seed, reseed and every `outbox.changed`). Rows are read only through `OutboxFeed::{rows,bubbles,settle}_for(&Agent)` (the key is `Agent::outbox_key()`, never the row id; a remote row's key is `<node id>/<job>` or the qualified `codex:`/`agy:` id, the `session` the follower daemon puts on the rows it republishes). `outbox.edit`, `outbox.remove` and `outbox.resend` carry that `session` next to the row `id` (`Request::outbox_*`, `Editing::session`), because the row id alone names no node: the cluster rules route those ops by `session`, and the daemon ignores the extra argument. The bubble's status line and buttons come from `outbox::bubble` (words in `chat.ftl` `chat-outbox-*`; Edit starts `Editing`, which puts the text in the reply box with an "Editing a queued message" line and Cancel, and Return sends `outbox.edit`; an edit the daemon refuses with `outbox::is_settled` words (no such message, being sent, in the session's queue), or whose row left the feed while Chat is acting (`Editing::lost`, checked in `sync_tools`, never while the edit's own `outbox.edit` request is in flight), ends with "Already sent" and keeps the text as the draft; any other refusal keeps the edit open and shows the daemon's words; while editing, the composer's attachments are neither shown nor sent and drops are ignored, `outbox_rows::attachments_for`, and Attach Files, Attach Folder, ⌘U and the drop target with its hint are off too: `chat::composer::add_allowed`, `add_menu_for` and `takes_drops`; the add button stays with Slash Commands only, disabled when nothing is left). The answer of a request in flight applies only to the edit that sent it (`Editing::same_edit`: chat row, outbox id and `round`, one number per Edit click; `outbox_rows::settle_edit`), so Cancel, Remove or another Edit pressed meanwhile are not overwritten by a late draft, leave or note; the edit code is in `chat/view/outbox_edit.rs`. An `in_queue` row hides the one matching entry of `Conversation::queued` (`outbox::hidden_queued`). Nothing is cleared without a click: Clear Box and Send is `outbox.resend {clear_box}`.
- `chat/asks.rs`, `chat/ask_drafts.rs`, `chat/sidebar_ask.rs`, `chat/view/ask_cards.rs`, `chat/ask_preview.rs` ([the note](../../docs/notes/ask.md)): Chat shows the questions agents ask. `asks::AskFeed` is the `asks` topic's rows by id (`seed` subscribes and reads `ask.list` once, off the UI thread with the other feeds; `apply` follows `ask.changed` and `ask.removed`; `session_source.rs` holds it beside the Outbox feed and reseeds it on a reconnect). `rows_for(&Agent)` reads by `Agent::outbox_key()` (a subagent's or delegated job's question carries its main session's key), oldest first; `needs_you` is true while any of the session's questions is open, and `sidebar_ask::with_asks` turns that into the Sidebar row's needs-you status. `asks::card(row, now_ms)` is the pure card model: the header (the agent's name, then its type, model, branch and `waited`, joined by the `chat.ftl` `chat-ask-*` words; "This session asks" for the main session and "This session or one of its subagents" for `unknown`), the question, the choices of an open card, and `closed_line` for a closed one ("Answered · Mac: Keep it", "Answered · main session", "Dismissed", "No answer in time", "Stopped waiting"); a closed card is dropped 10 minutes after `closed_ms` (`updated_ms` when it has none), and a closed card keeps no choices. `lost_line(reply)` says why an answer or dismiss didn't take ("Already answered · Phone", or the state's own line). The request builders (`ask.answer` with `choice` or `text`, `ask.dismiss`) sit in `acting.rs` beside the Outbox's. `ask_drafts::Drafts` is the per-question typed text, in-flight set and lost line (Return sends, a choice click sends `choice`, Dismiss; the reply box below is never touched); `view/ask_cards.rs` draws one `.part("Ask Card")` per card above the reply box, reusing the question card's parts. `NOTCHLING_RENDER_ASK=<state>` (`ask_cards::ASK_ENV`, rows from `ask_preview::STATES`: `open` (main session, no choices), `open-choices`, `unknown`, `answered`, `dismissed`, `gone`) puts that card in `--render chat`.
- `chat/view/composer.rs::BOTTOM_PAD`: The reply box's last row (pickers, hint, context chip, account, limit ring) is `CONTROL` high and sits `(sidebar::FOOTER_HEIGHT - CONTROL) / 2` above the window's bottom, so its center is level with the Sidebar's and the Details Panel's footer icons (22 pt up). Change `FOOTER_HEIGHT` or the row's height and the two lines part; the footer's top gap is a margin so its `min_h` is the whole row.
- `chat/view/composer.rs::sending_spinner`: The send button's spinner is a slot a `SpinLayer` or Core Animation paints outside the button, so the disabled button's 0.4 opacity never reaches it; it takes `button_look(Ghost, Disabled).opacity` into its own color, and must keep its name `send-spin` in `ROOT_SPINNERS` or it ticks the whole window ten times a second again.
- `chat/view/load.rs::finish`: A finished load carries the session it was started for; if another session was picked meanwhile its sessions list still counts but its conversation is dropped.
- `chat/view/load.rs::tick`: The Activity Line's clock has no spinner frames to ride on (its spinner is Core Animation's), so the tick redraws the window's outer parts once a second while it shows; a second opinion's card is redrawn once when its command ends.
- `chat/view/markdown.rs, page_panel.rs::file image`: GPUI sizes an image's box from its pixels, not its width, so the height must be computed from the image's shape (read from the file's first bytes) and never drawn larger than the file.
- `chat/view/markdown.rs, row_select.rs`: Selectable texts in a row are numbered in draw order and that order must equal `chat::blocks::plain_blocks`; a copy reads the model's blocks, and `check_blocks` render check enforces the match.
- `chat/view/markdown.rs::link press`: Link clicks run on listeners present every frame (`LinkPress`) and the text element takes no id of its own, since every id is state GPUI carries across frames for the whole conversation.
- `chat/view/page_panel.rs::edge drag`: The panel's drag edge sits over the hairline and just left of it, never over the web view, which would take the press.
- `chat/view/page_panel.rs::web view`: WebKit callbacks can arrive mid-update, so act a moment later on the app's queue; a click in the page gives its web view the keyboard and any click GPUI draws must take it back.
- `chat/view/prompts.rs::prompt card rows`: Card option rows use `w_auto` because the kit's `w_full` row does not resolve under wrapped text above it (a long path) and the rows shrank to their text.
- `chat/view/prompts.rs::screen read`: The screen read of a question moves the dialog's tabs, so it is never asked while acting is off or in a render, never two at once, and is retried only after a pause; each question is read once per read key.
- `chat/shell_live.rs`, `chat/view/shell_live.rs`: Claude Code writes a `!` command's `<bash-input>` when it starts and its `<bash-stdout>` only when it ends, so a login that prints a link and waits showed no output; while the newest item is a `!` row with no output and a local job works, the tick asks `session.shell_output` (every 3 s, 8 s while unchanged, never two at once, six empty reads or a failure back off) and the lines show as `Row::ShellLive` under the row with their links clickable, until the transcript's output replaces them. The reply is never written to a file or log.
- `chat/view/prompts.rs::send`: A successful answer hides only the prompt whose key was taken when the button was pressed, since the session may already have a newer one; a hook prompt is decided by its id, a state-read permission is typed into its terminal after checking the screen.
- `chat/view/render_map.rs`: Render-map outlines and badges are drawn by the root over the cached parts, never inside one, since a badge inside a part would redraw it and falsify the draw count it shows; the flash-clearing redraw is noted as the map's own.
- `chat/view/row_select.rs, select.rs::selection wash`: The selection wash is painted over the text, not behind it, because inline code paints its own background and hides a wash drawn first.
- `chat/view/select.rs::notes`: The cached conversation can skip its listener (which restarts the frame's notes), so a text outside it, like the file panel's, replaces its note by key each frame rather than appending one.
- `chat/view/shell_probe.rs::writers`: `lsof` for shell writers runs with `-w`, never `-b` (which skips the stat a file name needs, so lsof finds nothing), off the main thread; a shell not yet looked at counts as running with pid 0, never signalled. A probe that cannot start `lsof` records nothing: an empty answer means "no writer" and would end the shell for good.
- `chat/view/simulator/mod.rs::frames`: A frame identical to the last (hashed bytes) is not redrawn because every draw of the Chat window sets the cursor and fights AppKit's, flickering; old frames are evicted from the GPU atlas and a recording is stopped with SIGINT on drop.
- `chat/view/simulator/parts.rs::phone frame`: GPUI does not clip an image to its parent's rounded corners, so the screen image rounds its own corners.
- `chat/terminal_paint.rs, chat/view/terminal.rs::screen`: Every span of a row sits at `col * CELL` and the cursor at its own cell, so the screen's grid, not a font's advances, decides where text is: a row once flowed as one text per style, and `❯` was drawn 0.7 cell wider than its cell (10 px at 2x, measured on a render; Menlo's other glyphs match `CELL`), which shifted the rest of the line right while the cursor stayed on the grid and so covered the last typed letter. Only runs of plain ASCII share a span (Menlo's advance is `CELL`); any other cell is its own span, `cells` wide (`width` 2 for CJK and emoji), and the emulator's table (`width.rs`) stays the one place that says how wide a character is. The focused cursor is a filled block with the cell's own letter drawn on it in `Ink::OnGuide` (`Ink::Guide` is `Ink::Working`'s color in both appearances, a test holds it), never an opaque box painted after the text; an unfocused one is an outline over the unchanged text; a cursor on a wide cell or on its second half covers both cells.

A Linux machine whose file isn't in the dist folder is Ready, not Needs Build, when this build can download it from the release (`this_release`, passed to `rows_for` as `can_download`); the Fix does the download (`CurlDownloads` over the Machines runner, wired in `machines/data.rs`). Not Now hides the offer until the next build, kept in the feed, not in the sheet; closing the sheet mid-run doesn't allow a second run; Continue and Return do nothing while the admin password field is empty; Cancel sends no password (`AdminAnswer::None`), which the engine reads as Cancel.
- `crates/app/src/cluster/not_joined.rs`, `not_joined_view.rs`: The Cluster sheet's Not in the Cluster list is the registry's machines whose Joined step doesn't pass and that no member matches by id or name. Join Cluster on a row turns Cluster Node on and opens the flow for that machine. The Machines window (agent tier) gets no join token, so its card says to join from the Cluster sheet in Notchling.
