# app: notes for agents

## Why the code is this way

The code carries no comments (see [AGENTS.md](../../AGENTS.md)). What a change could break without knowing it, by file:

- `chat/activity.rs::stalled_prompt`: A request Claude Code sent on a connection that died while the Mac slept waits with no error; sending the prompt again starts a fresh one (Retry after `STALL_S`).
- `chat/activity.rs::working`: A session whose state is not working shows no live line whatever a stale transcript says, and a turn that ended while the session still works means a background command.
- `chat/claude_picker.rs::Choice`: A model or effort pick is an ordinary reply (`/model <full id>`, `/effort <level>`) with an argument, so the engine types it in; the bare command would open a terminal (`slash::route`).
- `chat/claude_picker.rs::hint`: A pick stands in for the transcript only while the transcript still says what it said at pick time, and for 30 s at most.
- `chat/cleared.rs::read_with_model`: A /clear in a background job starts a transcript that names no model; the model, effort and running subagents come from the transcript the clear ended (`locate::predecessor`), and the same inputs must give the same `Arc` back.
- `chat/composer.rs::menu_for`: Codex turns are `codex exec`, which has no slash commands, so its + menu has no Slash Commands row.
- `chat/data.rs::DataRoot (render)`: A render or fixture root never reads the real `~/.claude`; its rows never age out of Done and its Codex files are not date-filtered.
- `chat/data.rs::dedup of watched folders`: A lane's `projects` is a symlink to the main one, so config folders are deduplicated before scanning; each folder is watched once or the poll scans it twice.
- `chat/data.rs::own_dir`: The app's own data folder is apart from the Swift app's files and the daemon's `daemon/`: Swift copies over `data/antigravity` and keeps writing beside this app.
- `chat/delegated.rs::parents`: Delegated jobs are matched to a session by Claude Code's session id (the transcript file stem), and the transcripts its clears ended count too, so jobs stay with the row you see.
- `chat/drops.rs::local_target`: Agents link files relative to the session folder (Codex `<out/a.png>`), and macOS Finder fails with error -50 on a bare relative path, so links are resolved against the folder first.
- `chat/drops.rs::passing`: A screenshot thumbnail drop is a file macOS deletes soon (`TemporaryItems/NSIRD_screencaptureui_`); it is copied into `store/<now_ms>/` first so the session can still read it.
- `chat/file_panel.rs::read`: The file stamp is taken before reading so a write during the read shows as a change on the next look; reads are capped at `MAX_TEXT` and cut on a character boundary.
- `chat/inspector.rs::shells`: Shell running state needs a live process asking `writers` (a process holds the output file open); a reader without it shows a shell with no notification as ended.
- `chat/loader.rs::Loader`: The change between loads is computed off the main thread; the view only checks that the change starts from the conversation on show, and Antigravity's log is re-read only when its size or date changes.
- `chat/log.rs::diff`: The engine numbers items by line and keeps the newest few hundred, so a change is only a trimmed front, a grown end or an in-place edit; any other shape (ids not lining up) resets.
- `chat/view/load.rs::finish`: A finished load carries the session it was started for; if another session was picked meanwhile its sessions list still counts but its conversation is dropped.
- `chat/view/load.rs::tick`: The Activity Line's clock has no spinner frames to ride on (its spinner is Core Animation's), so the tick redraws the window's outer parts once a second while it shows; a second opinion's card is redrawn once when its command ends.
- `chat/view/markdown.rs, page_panel.rs::file image`: GPUI sizes an image's box from its pixels, not its width, so the height must be computed from the image's shape (read from the file's first bytes) and never drawn larger than the file.
- `chat/view/markdown.rs, row_select.rs`: Selectable texts in a row are numbered in draw order and that order must equal `chat::blocks::plain_blocks`; a copy reads the model's blocks, and `check_blocks` render check enforces the match.
- `chat/view/markdown.rs::link press`: Link clicks run on listeners present every frame (`LinkPress`) and the text element takes no id of its own, since every id is state GPUI carries across frames for the whole conversation.
- `chat/view/page_panel.rs::edge drag`: The panel's drag edge sits over the hairline and just left of it, never over the web view, which would take the press.
- `chat/view/page_panel.rs::web view`: WebKit callbacks can arrive mid-update, so act a moment later on the app's queue; a click in the page gives its web view the keyboard and any click GPUI draws must take it back.
- `chat/view/prompts.rs::prompt card rows`: Card option rows use `w_auto` because the kit's `w_full` row does not resolve under wrapped text above it (a long path) and the rows shrank to their text.
- `chat/view/prompts.rs::screen read`: The screen read of a question moves the dialog's tabs, so it is never asked while acting is off or in a render, never two at once, and is retried only after a pause; each question is read once per read key.
- `chat/view/prompts.rs::send`: A successful answer hides only the prompt whose key was taken when the button was pressed, since the session may already have a newer one; a hook prompt is decided by its id, a state-read permission is typed into its terminal after checking the screen.
- `chat/view/render_map.rs`: Render-map outlines and badges are drawn by the root over the cached parts, never inside one, since a badge inside a part would redraw it and falsify the draw count it shows; the flash-clearing redraw is noted as the map's own.
- `chat/view/row_select.rs, select.rs::selection wash`: The selection wash is painted over the text, not behind it, because inline code paints its own background and hides a wash drawn first.
- `chat/view/select.rs::notes`: The cached conversation can skip its listener (which restarts the frame's notes), so a text outside it, like the file panel's, replaces its note by key each frame rather than appending one.
- `chat/view/shell_probe.rs::writers`: `lsof` for shell writers runs with `-w`, never `-b` (which skips the stat a file name needs, so lsof finds nothing), off the main thread; a shell not yet looked at counts as running with pid 0, never signalled.
- `chat/view/simulator/mod.rs::frames`: A frame identical to the last (hashed bytes) is not redrawn because every draw of the Chat window sets the cursor and fights AppKit's, flickering; old frames are evicted from the GPU atlas and a recording is stopped with SIGINT on drop.
- `chat/view/simulator/parts.rs::phone frame`: GPUI does not clip an image to its parent's rounded corners, so the screen image rounds its own corners.
- `chat/view/terminal.rs::tab close button`: The tab's x has no tooltip of its own: a tooltip inside the tab's tooltip made the two take turns, redrawing and flickering the cursor; GPUI clips children to the tab's rectangle, not its corners.
- `chat/view/tools.rs::agy conversation fetch`: Antigravity conversation reads are one in flight per row, none out of order (`FetchGate`), and the daemon closes an agy session after ten idle minutes so Chat asks it to open again.
- `chat/view/tools.rs::agy delegation`: A session another `agy` (a delegation) holds shows live state but Stop cannot reach it (`agy.cancel` ends only this daemon's own turn), and a reply through a second `agy` would stop the other's work.
- `chat/view/tools.rs::draft first message`: A draft row whose first Codex message is still starting must not take another send (it would start a second session); the row follows the real session when named, else the text goes back into the box.
- `chat/view/tools.rs::stop and retry`: After Stop a second Esc to a stopped session would open the terminal's rewind menu, so Stop is remembered for up to 20 s; Retry stops the stuck turn first so a late answer cannot land with a second copy queued behind it.
- `crates/app/src/accounts/flows.rs::SIGN_IN_HOSTS`: The hosts a sign-in link may open mirror the engine's (`AUTHORIZE_URL`, `SIGN_IN_PREFIX`, claude.ai, Google); keep them in sync, and open only `https` links with no user or port on exactly one of them.
- `crates/app/src/accounts/menu.rs::move_all_target`: Move All sends `None` only for the main login; a lane or saved account without an account id is refused, because `null` would move every session to the main login.
- `crates/app/src/accounts/store.rs::Accounts::gate`: The lists are read whether the `accounts` switch is on or off; every other op is sent only when it is on, so a control that slipped past its disabled state still reaches no login.
- `crates/app/src/accounts/store.rs::refresh`: Syncing live logins and reading limits happens at most every `SYNC_EVERY` seconds, since the daemon publishes `providers.changed` per list read and syncing on every event would feed itself.
- `crates/app/src/accounts/store.rs::refresh_all`: A forced refresh asks providers to re-read limits before the lists are read, because a list's own sync holds the daemon's slot for that provider and the forced read would be dropped.
- `crates/app/src/accounts/wire.rs::readers`: Account, provider, limit and cost replies never carry a token, cookie or value, and the readers are tolerant: a missing field is left out and never fails the whole read.
- `crates/app/src/acting.rs::Request::answer`: A hook-held prompt is answered by its prompt id (`hook:<id>`), never the row id, so the answer reaches the prompt the card showed; other questions are typed into the row's dialog page by page.
- `crates/app/src/actions.rs::Actions::choose`: The user's acting choice goes to the daemon first and is saved to settings after, so "off" reaches the daemon even when the settings file can't be written; `refresh` only reads and never turns acting on.
- `crates/app/src/actions.rs::CALL_TIMEOUT`: A reply that types into a session attaches (up to 15 s), types and detaches (3 s), so the app waits longer than that; a 5 s limit reported failure for a message the daemon still sent, and a resend doubled it.
- `crates/app/src/actions.rs::CHOICE_KEY`: The `actingOn` key is not in the engine's settings key list, so it is written past the store's key check.
- `crates/app/src/chat/markdown.rs::LinkPress`: Link clicks are tracked from mouse down to mouse up here, not with GPUI's clickable text, which listens for the release only after a redraw and missed quick clicks on a long conversation.
- `crates/app/src/chat/markdown.rs::link destination`: A `(<url>)` destination may hold spaces, because Codex links its generated images that way; keep parsing it as the text inside the brackets.
- `crates/app/src/chat/outgoing.rs::GRACE_MS`: A delivered bubble is dropped after a grace time even if the transcript never shows the same words, since slash commands and pasted images are stored in other words.
- `crates/app/src/chat/outgoing.rs::normalize`: A sent shell command "!ls" is read back from the transcript as "! ls", so both sides are normalized before the sending bubble is matched with the transcript message.
- `crates/app/src/chat/page_panel.rs::live page navigation`: A live claude.ai page may only load https on the allowed hosts (claude.ai, its Artifact host, the bot check), about:, and blob: of those; the URL is rebuilt from the id so nothing else the link held is loaded.
- `crates/app/src/chat/page_panel.rs::web view frame`: The page's web view is a native view above everything GPUI draws, so it hides while a sheet, the phone popover or the part names are open; its frame flips y for an unflipped AppKit parent and snaps edges to device pixels.
- `crates/app/src/chat/prompt_flow.rs::NOT_PERMISSION`: The card recognizes the daemon's "not a permission any more" refusal by a marker string (`Failure::NotPermission`); a test pins it against the engine's wording, so change both together.
- `crates/app/src/chat/prompts.rs::DIALOG marker`: The dialog-refusal marker must stay in sync with `engine::reply::exec::Failure::Dialog`, since Chat tells "a question or permission is open" from other send failures by its text.
- `crates/app/src/chat/prompts.rs::NO_ALWAYS`: A file-edit terminal dialog has no "don't ask again" (only "allow all edits this session", a wider answer), so Edit/Write cards must not offer Always Allow; permissions from a job's state are answered in the terminal with the tool and command the card showed.
- `crates/app/src/chat/prompts.rs::state-summary permission`: A background job writes its question to the transcript only once answered and its state summary lacks later questions and breaks on brackets, so Chat reads the question off the screen (`session.question`, once per summary) and that read wins.
- `crates/app/src/chat/rows.rs::expand_tabs`: GPUI shapes a raw tab as one odd glyph, so view models turn tabs into spaces up to the next stop; a Read's `cat -n` output arrives with its first line's leading spaces trimmed, so the gutter is rebuilt from the widest number.
- `crates/app/src/chat/sidebar.rs::PendingSession`: A session the sidebar doesn't list yet is waited for only a couple of loads or a few seconds (a New Session job longer), then dropped, so a row that turns up late never steals the selection.
- `crates/app/src/chat/sidebar.rs::sections`: A Claude Code session that has exited is not listed under Done (the maintainer asked on 2026-11-10); search still finds it.
- `crates/app/src/chat/simulator.rs::key script`: `simctl` cannot press Home or rotate a device, so those keys go through AppleScript to the device's Simulator window, whose name is "<device> – <runtime>" with quotes and backslashes escaped.
- `crates/app/src/chat/terminal.rs::menu commands`: Menu commands (/mcp, /plugin, a bare /model) write nothing to the transcript, so they run in a terminal tab attached to the job: clear the input with Ctrl+E, Ctrl+U (never Ctrl+K or Esc), then the command, then Enter, each after a pause.
- `crates/app/src/chat/used.rs::visible`: Codex and Antigravity rows show in the Sidebar only if used in Chat or recently active, because agents hand them jobs elsewhere with --delegate; a draft or a session that another session delegated to is hidden until used here.
- `crates/app/src/chat/view/composer.rs::add files shortcut`: The editor consumes every key, so the add-files shortcut is caught on the way down at the card, before the editor sees it.
- `crates/app/src/chat/view/conversation_list.rs::replace`: Splicing a list item resets its offset, so a splice of the row at the scroll top saves the scroll top and puts it back when the range keeps its size.
- `crates/app/src/chat/view/conversation_list.rs::sync`: Following the end is forced only on a send or a session pick; pulling back to the end on every draw undid small scroll-up steps, so a draw with nothing new leaves the reader where they are.
- `crates/app/src/chat/view/copy.rs::Keys`: With nothing focused, GPUI's action path is the window's outermost node alone, so a Copy handler on the root never fires; a zero-size focus anchor with its own handle (not the root's) keeps the root on the path without stealing focus from the reply box.
- `crates/app/src/chat/view/drop.rs::hint`: A GPUI group style is computed only on an element with a hitbox, so the drop hint names a group of its own, which gives it a hitbox that blocks nothing; a screenshot thumbnail's short-lived file is copied under `drops/` first.
- `crates/app/src/chat/view/limit_ring.rs::arc`: GPUI path strokes have butt caps, so the limit ring's round ends are drawn as small discs.
- `crates/app/src/crash_log.rs::append`: The crash log is opened with `O_NOFOLLOW` and mode 0600 because a panic message can quote private text; errors are ignored and no date crate is used since the hook runs mid-panic.
- `crates/app/src/dock.rs::main_menu`: The main menu shown while a titled window is open has no Hide item, because hiding the app would hide the notch too.
- `crates/app/src/mac/bench_events.rs::Injector`: GPUI's `dispatch_event` is private and AppKit's own constructor reports button 0, so bench clicks and scrolls are built from Core Graphics events and the first call finds the screen y offset.
- `crates/app/src/mac/hotkey.rs::handler`: The Carbon hot key handler returns `eventNotHandledErr` unless one of our keys was pressed and handled, so other libraries' keys in the process are not swallowed; handlers sit in a thread-local on the main thread.
- `crates/app/src/mac/restart_notice.rs::RestartNotice`: The restart notice never takes focus or activates the app, so a key pressed elsewhere cannot land in it, and a switch that fails to turn back on is asked about once, never retried in a loop.
- `crates/app/src/mac/shell.rs::quit`: Every way out (Cmd-Q, Dock Quit, tray Quit, logout) ends in `applicationWillTerminate`; GPUI runs that closure itself, not under its 100 ms limit, so waiting there for reviews to end finishes before exit.
- `crates/app/src/mac/vault_prompts.rs::VaultPrompts`: An approval window brings the app forward once as it opens and Allow stays unarmed briefly; a request form opens without focus; closing is Deny or Cancel, and only an app following `vault` can show them.
- `crates/app/src/machines/data.rs::MachinesData`: Without `--live` every process goes to the engine's `Refusing` runner and without `--vault` there are no secret values; a fixture root never runs a process or opens the vault, and a render writes nothing.
- `crates/app/src/machines/forms.rs::type_key`: Form fields take printable text only, so a paste cannot carry a control character into an ssh command; Add works only after a Check for the same name, host and user.
- `crates/app/src/machines/model.rs::edit_registry`: A registry edit loads the latest file, changes it and saves under the engine's lock, because the engine saves what its checks learn; never save from the last render.
- `crates/app/src/machines/model_fixes.rs::request_*`: Every Fix starts in a `request_*` a button calls and only shows the plan; `confirm` takes the single click on Run, and opening the window, Refresh, Check, Add and vault changes run checks only.
- `crates/app/src/machines/model_sheet.rs::Sheet`: One Fix sheet at a time: a request for another while one shows is refused so the Run on screen is the plan shown, and the admin password lives only while its sheet does and never reaches a log.
- `crates/app/src/machines/morning_view.rs::retry_push`: Retry push is offered only for a merge whose check passed; a merge on main without that proof can only be undone.
- `crates/app/src/notch/answer.rs::press_key`: Control characters never enter a notch answer's text, so it can't carry an Esc or the end of a bracketed paste into the terminal.
- `crates/app/src/notch/answering.rs::send / model.rs::answer_key`: The answer key is taken when the button is pressed and only that prompt is hidden afterwards, since the session may hold a newer prompt by the time the reply returns; Chat shares the answered set.
- `crates/app/src/notch/layout.rs::canvas_size`: The notch canvas must stay as small as the largest shape: GPUI backs the whole canvas with Metal drawables (three plus path textures at Retina scale), and a screen-wide one used most of the app's memory.
- `crates/app/src/notch/layout.rs::hit_test`: The shape's top edge counts as inside and the right edge is half-open, because a pointer pushed to the top of the screen reports exactly that y and `NSMouseInRect` counts it in.
- `crates/app/src/notch/model.rs::question_summary`: A background job writes its AskUserQuestion to the transcript only once answered; while open its state holds just an "answer: ..." summary, and several questions or ones with brackets need a screen read.
- `crates/app/src/notch/panel.rs and search/panel.rs::style`: GPUI opens every window Titled and AppKit keeps it below the menu bar, so the notch and search panels are made borderless and non-activating and their frames set again after opening, on the first tick.
- `crates/app/src/notch/panel.rs::poll`: An open Antigravity session's lines are read from the daemon in peek mode so the poll never keeps an idle `agy` process alive; the notch can't read its files.
- `crates/app/src/notch/pet_view.rs`: GPUI 0.2.2 can't rotate text, so the pet rolls without spinning; its reach (`PET_REACH`) must stay within the canvas margin.
- `crates/app/src/notch/requests.rs::read_dir`: The notch never writes a response, removes a file or signals a process for the Swift hook's `requests/<id>.json`; it treats a file older than the hook's 290 s wait as stale.
- `crates/app/src/notch/source.rs::DataRoot`: A fixture root lays folders out as `<root>/claude` and `<root>/notchling`, never `.claude`, which the repository's zones protect; the Antigravity summaries copy lives in the app's own folder, never Antigravity's or another process's.
- `crates/app/src/pages/dates.rs`: Page dates are formatted in UTC because the app has no time zone reader yet; a date off by some hours was judged better than a new crate.
- `crates/app/src/pages/local.rs::library_copy`: A page copy path must resolve (links followed) into a folder inside `pages_dir`, never the root (`pages.json` lives there and the root is every page's folder), since the web view gets read access to that folder.
- `crates/app/src/pages/set.rs::PageSet`: A page window is held until the person closes it, and a window minimized to the Dock counts as open although AppKit reports it not visible; closing must tell the owner so the page stops running.
- `crates/app/src/pages/web.rs::PageWindow::drop`: wry keeps a dropped web view alive on purpose (releasing it crashes), so it is sent to a blank page before the window closes or the page's scripts and media would keep running.
- `crates/app/src/pages/web.rs::PanelWeb::focus_gpui`: After a click on the page the web view is first responder and GPUI's view never takes it back by itself, so the app hands the keyboard back to GPUI's view or the reply box gets no keys.
- `crates/app/src/phone/approval.rs::WAIT_MS`: The pairing prompt's wait mirrors the daemon's `APPROVAL_WAIT` (120 s); a request older than that is already refused, so its prompt goes away.
- `crates/app/src/phone/bridge.rs::BRIDGE_KEY`: `bridgeOn` is not in the engine's settings key list, so it is written past the store's key check.
- `crates/app/src/phone/bridge.rs::Bridge`: The daemon's bridge is off at every start; `Bridge::refresh` only reads, and only `Bridge::choose` (the user's switch) sends `bridge.set`, daemon first, then `bridgeOn` in `settings.json`.
- `crates/app/src/phone/pairing.rs::PairingFeed`: The daemon asks for a phone's answer only while an app client follows the `bridge` topic; the app's own connection does that, and an answer goes over a separate call, never the following connection.
- `crates/app/src/phone/pairing.rs::PairingFeed`: A lost connection or the bridge going off clears the queued prompts, since the daemon has already refused those phones.
- `crates/app/src/phone/prompt_view.rs::PromptView`: Esc denies a pairing request but Return does not allow it, so a key pressed in another app just before the window appeared cannot let a phone in.
- `crates/app/src/phone/wire.rs::devices`: A device row without an id is skipped, since Revoke could not name it.
- `crates/app/src/phone/wire.rs::readers`: The phone ops' JSON is not fixed by the plan, so readers accept snake_case or camelCase, a state as word or flag, and times in ms or seconds (a number below 100 billion is seconds); a missing field is left out, never a failed read.
- `crates/app/src/search/marks.rs::clean`: Highlight ranges from the daemon are sorted, merged and snapped to character boundaries before drawing, because GPUI's `StyledText` panics on overlapping, unsorted or mid-character ranges.
- `crates/app/src/search/panel.rs::open`: A non-activating panel only gets keys while its app is active, so showing it activates Notchling; Esc returns focus to the previous app, but opening a page or session does not.
- `crates/app/src/session_source.rs::SessionSource`: UI threads only read the latest view (a lock and a clone), never the socket; a fixture root or render gets no configuration, so no socket is touched and no daemon is started.
- `crates/app/src/session_source.rs::connect`: The client checks who serves the socket (`server_trusted`) before hello, subscribes before listing so no change falls between, and `ensure_daemon` starts a daemon at most once per run and only from an app bundle or cargo target folder.
- `crates/app/src/switches/feed.rs::SwitchFeed::choose`: The daemon is told first and the choice kept second, so turning a switch off always reaches the daemon even when the settings file cannot be written.
- `crates/app/src/switches/feed.rs::connect`: The feed subscribes before it reads settings.switches and vault.pending on the same connection, so the first events are never older than the read and an approval asked while the app was away still prompts.
- `crates/app/src/switches/feed.rs::connection lost`: When the connection drops or the vault switch goes off, pending approvals and request forms are dropped, because the daemon denied them when the app left.
- `crates/app/src/switches/feed.rs::providers sync`: The daemon publishes a sync change for every providers.list including the app's own refresh, so the feed must not count those as changes or each refresh would trigger the next.
- `crates/app/src/switches/mod.rs::switch choices`: The app never turns a switch on from the remembered choice in its settings file alone, since any agent can write that file; only a click or a confirmed restart notice sends settings.set_switch.
- `crates/app/src/switches/restart.rs::Restart::chose`: A switch the user turned off in the app is not restored after a daemon restart; only switches seen on, or remembered on and never turned off, come back.
- `crates/app/src/tools/agy_context.rs`: Antigravity context size is input_tokens plus cache_read_tokens (counted apart) of the latest PLANNER_RESPONSE in its transcript log, since the ACP stream reports it only at turn end.
- `crates/app/src/tools/agy_list.rs::AgyList`: The Antigravity summaries database is read only through a copy in the app's own folder, never the original, and AgyList::shared makes the notch and Chat share one read.
- `crates/app/src/tools/agy_permission.rs::ordered_options`: Antigravity permission options are listed one-time allow first, other allows, then rejections, so the first row is the safe default; answers go by the prompt's own session id, not the selected row.
- `crates/app/src/tools/fetch_gate.rs`: Chat keeps at most one agy.conversation read in flight per row and never lets an older answer replace a newer one shown, or a streaming turn would draw the conversation going backwards.
- `crates/app/src/tools/live.rs::ToolLive::overlay`: A daemon row carries its event's time, so the session's last-used time must stay the file's, or a closed row reopens on every event.
- `crates/app/src/tools/open_gate.rs`: The daemon closes an agy session after ten idle minutes, so Chat must ask agy.open again when it closes, never sooner than RETRY_MS, and forgets all asks when acting turns off or on.
- `crates/app/src/tools/requests.rs::agy.conversation`: A long session comes back cut to its newest items because the daemon answers in one 1 MiB line; reads use peek so a list poll does not count as use, and an agy held by a delegation is read only.
- `crates/app/src/tools/second_opinion.rs::store`: Second opinions are kept in the app's own app/second-opinions document, never the Swift app's second-opinions.json, and run the notchling binary beside the app because the app executable rejects delegate.
- `crates/app/src/transcripts.rs`: A session that entered a worktree mid-run has its transcript moved to the worktree's project folder while job state names the old path, so a miss falls back to finding the file by name; misses are retried only after MISS_RETRY.
- `crates/app/src/vault/approval.rs::ApprovalModel`: Each vault approval gets its own window bound to one approval; Allow arms only ARMING_MS after the window appears or becomes key, closing is Deny, and it resolves only after the daemon took the answer.
- `crates/app/src/vault/approval.rs::display`: The approval shows the command with newlines and invisible or bidi characters made visible, and prefers the daemon's verified folder and process chain over what the agent claims.
- `crates/app/src/vault/form.rs::Form`: Return never saves an agent's vault request, so a key pressed in another app cannot add a secret; a request that moves the URL to another origin needs an explicit confirmation before Save is live.
- `crates/app/src/vault/form.rs::secret`: The typed value goes out once in vault.save and is cleared from memory at once; it is never shown, copied, cut, or printed by Debug, and an empty value keeps the stored one.
- `crates/app/src/vault/wire.rs::Verified`: The approval's verified object comes from the daemon's socket peer, not from the agent's words; missing or null means nothing was checked, which is neither a match nor a mismatch. The app never calls vault.use.
- `crates/app/src/welcome/defaults.rs::SystemDefaults`: The Swift app's settings are read only with defaults export <domain> - (never another verb), because the cfprefsd cache is current and the plist file may not be; existing app settings win on import.
- `crates/app/src/welcome/facts.rs::is_swift_app`: The Swift app is told from this app by bundle id, since this app installs under the same name Notchling.app and macOS file names ignore case.
- `crates/app/src/welcome/hooks.rs`: The app never edits Claude Code's settings.json itself; install.plan and install.apply go through the daemon, and the default args cover hooks and the notchling-* skills since nothing else installs the skills.
- `crates/app/src/welcome/own.rs::set_switch`: A settings.json that cannot be read is moved aside as settings.json.unreadable-<secs> so the user's off choice is still written and never lost.
- `crates/app/src/welcome/updates.rs::CurlFetcher`: The curl fetch passes -q first because curl otherwise reads ~/.curlrc, which could add an output file, a proxy or plain http.
- `crates/app/src/welcome/updates.rs::check`: The update check makes no request unless NOTCHLING_RELEASES is exactly on, never downloads or installs, reads only version numbers and https github.com links from the feed, and refuses feeds over the size cap.
- `crates/app/src/welcome/window.rs::open_first_run_once`: The first-run flag is set before the window opens, so it shows once even if the app quits with it up, and an unwritable settings file does not make it reopen every launch.
- `crates/app/src/welcome/xml.rs`: The XML reader skips a DOCTYPE without resolving it and supports only the five named entities and numeric references, so no entity can name a file or URL; depth and text are capped.
