# cluster-net: notes for agents

## Why the code is this way

The code carries no comments (see [AGENTS.md](../../AGENTS.md)). What a change could break without knowing it, by file:

- `crates/cluster-net/src/identity.rs::load_or_make`: A node's certificate (v3, ECDSA P-256, CN `notchling-node`, 20 years) is made once per data folder and never replaced: its fingerprint is the node's id in every other node's `cluster.db`. A file that doesn't parse, half an identity or a link in place of either file is an error, never a reason to make a new one. `Debug` prints the fingerprint only.
- `crates/cluster-net/src/tls.rs`: Pinning replaces chain validation: the server takes a client certificate only if its SHA-256 is in `Pins` (or the join window lets one unpinned peer in), the client takes the server only if it is the fingerprint the caller expected. Certificate dates and names are not checked; the handshake signatures are, with ring's verifiers. TLS 1.3 only, no tickets, no resumption, no SNI.
- `crates/cluster-net/src/pin.rs::Pins`: The join window (`set_join_open`) admits one unpinned peer at a time, only while a join is open; the slot frees when that link ends or when the joiner gets pinned (the core pins Pending members). The verifier asks `may_handshake`, then the accepted link takes the slot with `admit`, so a handshake that fails never holds it.
- `crates/cluster-net/src/link.rs`: In TLS 1.3 a client finishes its handshake before the server has judged its certificate, so the server sends one empty line once it has admitted the peer and `dial` waits for it: a refused dial is an error on both ends, never a link that dies on its first read. One thread per link does both reading (20 ms polls) and writing, so no lock is ever held across socket I/O. The writer queue holds 256 lines; a full queue closes the link rather than blocking the caller. `LinkEvents::opened` is called before any line of that link, and `closed` names the link's id so a late close of an old link can be told from the current one.
- `crates/cluster-net/src/listen.rs::TcpTls`: Listens and dials only on Tailscale addresses (`notchling_platform::net_if`), or only on 127.0.0.1 when `loopback_ok` (a dev build with `NOTCHLING_CLUSTER_LOOPBACK=1`, decided by the daemon). A peer outside those ranges is dropped before the handshake. At most 64 links at once.
- `crates/cluster-net/src/mem.rs::MemTransport`: The in-process transport for tests checks fingerprints, pins and the join window exactly as `TcpTls` does, and splits lines with the same 1 MiB cap, so a test over it means the same as one over TCP.
