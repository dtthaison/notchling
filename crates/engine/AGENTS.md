# engine: notes for agents

## Why the code is this way

The code carries no comments (see [AGENTS.md](../../AGENTS.md)). What a change could break without knowing it, by file:

- `crates/engine/src/accounts/antigravity/login.rs::account`: The older login format (file mirror) has an id_token whose sub is the id; the newer one agy writes names only the email, so it matches a saved account by email. A newer login can't go in the mirror file, so that file is deleted.
- `crates/engine/src/accounts/antigravity/quota.rs::csrf_token`: The CSRF token goes only into a request header and is never stored, logged or returned. The lsof call needs -a, or it lists every TCP listener on the Mac.
- `crates/engine/src/accounts/antigravity/quota.rs::servers`: Limits come from a local language server (Antigravity.app, the IDE, or any agy acp) on a random port; the apps want the CSRF token from their own command line, agy takes none. Skip servers that are signed out or on another account.
- `crates/engine/src/accounts/antigravity/quota.rs::user_status`: The plan name is userTier.name; planInfo.planName is the Codeium plan and always reads Pro. Try the lowest port first: the HTTPS port opens before a plain one just above it.
- `crates/engine/src/accounts/antigravity/store.rs::add_account`: Add Account must delete the Keychain item as well as the mirror file, or Antigravity restores from the item and never shows its sign-in screen.
- `crates/engine/src/accounts/antigravity/store.rs::idle_for_auto_switch`: An automatic switch needs Antigravity closed and no agy running, since a running agy keeps the login it started with and may write it back. Last-read limits are kept in notchling.db because the server answers only while Antigravity is open.
- `crates/engine/src/accounts/antigravity/store.rs::replace guard`: Antigravity's own item is never split and is updated in place to keep its read access. A login too long for one security -i line is refused before anything quits or changes.
- `crates/engine/src/accounts/antigravity/store.rs::switch`: Antigravity's login lives in two places, the Keychain item (service gemini, account antigravity, go-keyring base64) and ~/.gemini/jetski-standalone-oauth-token. A switch must set both, with the apps quit.
- `crates/engine/src/accounts/claude/config.rs::set_oauth_account`: The text is read again just before the write because Claude Code writes ~/.claude.json often. The backup is .claude.json.notchling-backup and both files keep their mode.
- `crates/engine/src/accounts/claude/lanes_side.rs::close_lane`: Before a lane's item is replaced or removed, its claudeAiOauth must match the account's saved slot. Switching or closing a lane first copies the login back, unless the profile endpoint says it belongs to another account.
- `crates/engine/src/accounts/claude/mod.rs::ClaudeAccounts`: One lock covers every operation, Keychain and network included, so a sync can't write back a list read before a removal. snapshot reads a copy so it never waits behind a switch stuck on a Keychain prompt.
- `crates/engine/src/accounts/claude/mod.rs::note_active`: Every place `state.active` is set (`capture`, so a sync and any op that starts with one, and `switch_for` after `activate`) calls it, and it pushes an `account.switched` event (`accounts/claude/events.rs`: the from and to account ids, a cause from `SwitchWhy`: `user`, `move_all`, `limit` with its window and percent, or `other` for one noticed at a sync) when the account differs from the last one recorded (`State::logged`, seeded once per run from `env.history`, which the daemon backs with the `account.switched` rows of `events.db`, so a restart never records the same account twice). It runs under the store's lock but does no Keychain or network call, and an event that can't be queued never fails a switch. Claude Code is the only tool it covers (Desktop's account is in its path, Codex's in the rollout, Antigravity is one account); a lane switch does not change the main login and records `lane.changed` only. A login added, removed or renewed is `account.login`.
- `crates/engine/src/accounts/claude/mod.rs::switch`: Before replacing Claude Code's login, check the live claudeAiOauth reads back from the active account's saved slot. Claude Code renews in place, so the live item may hold the only working refresh token. A failed half-switch is undone through undo_keys.
- `crates/engine/src/accounts/claude/tokens.rs::renew`: Only a saved login that is live nowhere (not main, not in a lane) is ever renewed, rechecked against ~/.claude.json and lanes.json just before the request. The read-only main-token path has no renewal at all.
- `crates/engine/src/accounts/codex/live.rs::write_auth`: auth.json is written under an exclusive flock on Codex's own auth.lock, waiting a bounded time and writing nothing if it can't get it, so a write never lands in the middle of Codex renewing the file. A symlinked auth.json is followed.
- `crates/engine/src/accounts/codex/login.rs::idle_for_auto_switch`: An automatic Codex switch runs only with no codex process (CLI or Chat turn) and the ChatGPT app closed. The managed app server alone doesn't count. An expired Codex token gives no limits until Codex renews it.
- `crates/engine/src/accounts/codex/standing.rs::standing`: The wham usage response carries more than two windows: `rate_limit_reached_type.type` (a `credits` type, `workspace_owner_credits_depleted`, means the workspace's pool is empty and Codex refuses while both bars can still read under 100%), `rate_limit.allowed` and `limit_reached`, and `credits`. It is read into `Standing` with fixed words only: no text from the response (the upsell title and description, a balance that isn't a plain positive number up to 16 characters) reaches a reply. A read that has none clears the account's old one in `CodexStore`, so "out of credits" never outlives the read that said it. ChatGPT's own page treats `allowed: false` as 100% used; here the bars keep the response's own percents and the standing says why Codex refused. `model_usage`, `spend_control`, `promo` and `rate_limit_reset_credits` are not read.
- `crates/engine/src/accounts/codex/store.rs::switch`: A switch writes auth.json only once the live login reads back byte for byte from its saved copy. The ChatGPT app quits first and reopens, and the app-server restart sends all output to /dev/null so a daemon holding a pipe can't hang the read.
- `crates/engine/src/accounts/desktop/files.rs::backup`: Cookies.notchling-backup is written once and kept, so it is always the file Notchling found. Account ids become file names only if they are letters, digits and dashes, up to 64.
- `crates/engine/src/accounts/desktop/files.rs::restore`: Claude Desktop's account is decided by claude.ai web session cookies, not the token. Switching copies the whole Cookies file, deletes Chromium's stale write-ahead files, sets lastKnownAccountUuid and bootSideSessions, and only while Desktop is quit.
- `crates/engine/src/accounts/http.rs::LiveHttp`: LiveHttp calls only the two hosts Claude's login uses, and a fixture root gets a client that sends nothing.
- `crates/engine/src/accounts/json_splice.rs::set_top_level`: ~/.claude.json and the Keychain item change by splicing one top-level key in the text, never by parsing and rewriting, so key order, spacing and number spelling stay as Claude Code wrote them. The result is parsed back and checked.
- `crates/engine/src/accounts/keychain.rs::set`: security -i can exit 0 after a command inside it failed, so every write is read back. security -w prints a value with a newline as hex. A value with a control character can't go as quoted text and must go as hex.
- `crates/engine/src/accounts/keychain.rs::text_line`: Items another tool reads (Claude Code's login) too long as hex go as quoted text with backslash and quote escaped. Own saved copies are split by chunked.rs with a sha256 header, and a damaged value is an error, never a wrong login.
- `crates/engine/src/accounts/mod.rs::Secret`: Tokens travel as Secret and Login, whose Debug and Display print no value, so a stray format can't leak one into a log or error. Any HTTP request or response type holding a token hides it in Debug too.
- `crates/engine/src/activity/reply.rs`: An Activity row is built from an event's own fields by allow-list, never by copying a line: `detail` is only a vault use's secret names, a setting's key, a switch's name or a refusal's reason, cut to 120 characters, and a `result` is the event's `result` or `action` field. `refs` carry ids (a session, folder, account, device), never a name; the daemon's `names` callback turns a device id into the phone's name for `who`. `list` halves the rows until the JSON is under 900 KB, since the local API's line is 1 MiB. `import.rs` reads the old `audit.jsonl`, `remote-log.jsonl` and `account-log.json` once into `legacy` rows, with the same allow-list; `db.rs` is `daemon/events.db` (rows expire by kind, `prune`).
- `crates/engine/src/logs/`: The Audit's files and keys. `AuditDir` is `audit/YYYY-MM.jsonl` (0700 folder, 0600 files, a month named by the line's own time) and `legacy/`; `move_legacy` moves the old `audit.jsonl` files there once and never rewrites them. `KeyStore` is the trait the sealing key sits behind: a file store (`daemon/audit-key`, under a fixture root and in every test), a memory fake and the Keychain store (`keys_mac.rs`: `security_framework::passwords`, generic password items `dev.notchling.audit` for the key and `dev.notchling.audit.head` for the checkpoint, the newest seal, which is what makes a cut tail show). A real data folder uses the Keychain only; a test must never reach it. A key that can't be read leaves the lines unsealed, never blocks them: every `KeyStore` call can block on a Keychain prompt (a new ad-hoc build is a new identity, so the ACL asks again), so the daemon calls them only from its own threads (`notchlingd/src/log_keys.rs`), never on its start path or under a lock. `MemoryKeyStore::hold` and `release` make every call wait, for a test of that. The checkpoint is written at most every 10 s and 5 min, not per line.
- `crates/engine/src/awake/decide.rs::busy`: Ported from the Swift `AppDelegate.refresh`: a session counts only while its group is Working (Needs Input and Completed do not), and a Codex turn or an Antigravity session counts only when Notchling's own runner has it running, as the Swift notch merged it; a Codex session run in Codex's own terminal does not hold the Mac awake. The daemon does not know which sessions a user hid in the notch, so a hidden working session still counts (the Swift app dropped it). Long `sd` runs (`RunWatcher`) are not ported, so they hold nothing yet. `want` asks for the work only in `Mode::WhileWorking`; `read` takes an unknown mode word as Off, and never looks at the Awake v1 flag `active` (the settings migration folded it into `mode`).
- `crates/engine/src/awake/hold.rs::Awake::take`: A change of kind (the display flag flipped while held) acquires the new assertion before the old one drops, so the Mac is never unprotected between them, and a refused swap keeps the old hold. A refusal is reported once per reason and retried at every tick, as the Swift controller retried at every poll; going back to nothing wanted clears it.
- `crates/engine/src/awake/real.rs::REASON`: The assertion's name is what `pmset -g assertions` shows, the Swift app's text word for word, so the maintainer finds it the same way. `FakePower` is what a daemon over a fixture root gets (`notchlingd/src/awake_loop.rs::power_for`): no test or dev run holds a real assertion.
- `crates/engine/src/awake/state.rs`: The wire form of what the daemon holds, shared by the daemon (`awake.state`, `awake.changed`) and the app: `{"holding": "system" | "display" | null}`. A word it doesn't know reads as no state at all, so an app talking to a newer daemon shows the cup empty, never wrong.
- `crates/engine/src/bridge/agents.rs::session`: A row with a `node` is another computer's session: its id stays the qualified row id (the owner's session id is meaningless here), its control is `Job` of that id when the owner's row can be replied to, and its pid is dropped. `Session.node` is `{id, name, online}` and absent for the Mac's own rows, so an older phone sees the same list as before. A photo to a remote row is refused at `session.image.begin` and `end` ("Photos to a session on another computer come later."), since the file would be saved here and its path typed into the owner's session. `Sources::follow_remote` is called by `chat_messages` for a row with a node, so the daemon can keep its mirror fresh while the phone has the session open.
- `crates/engine/src/bridge/router_machines.rs::cluster_promote`: It is dispatched on the Mac the phone reached and never goes through the relay (a promote must not wait on the primary that is down), it needs `acting_on()` like `inbox.answer`, and its audit op carries the refusal reason (`cluster.promote:refused:acting_off`). Only `step`, `relayed`, `text` and `needsConfirm` of the daemon's answer reach the phone. `cluster.machines` answers `{machines: []}` when the backend has no cluster, so an older phone never asks and a phone that does sees an empty list, not an error.
- `crates/engine/src/bridge/connection.rs::Connection`: At most one phone frame is in flight, and a device-window frame offered while another is still going out is dropped, never queued. A second send to a session already running is answered busy.
- `crates/engine/src/bridge/live.rs::recent_projects`: The phone's folder list tests each folder with `is_dir` on this Mac, so a row with a `node` (another computer's session) is skipped: its `cwd` is a path there, and one that happens to exist here would be offered as a place to start a session.
- `crates/engine/src/bridge/foreign.rs::message_id`: Phone message ids are the first 16 bytes of SHA-256 of a seed from session and item ids, uppercase UUID. They must equal the Swift app's, and stay stable so the hub pushes each message once.
- `crates/engine/src/bridge/foreign.rs::messages`: A last item that may still grow (an Antigravity stream, a tool row gaining calls) is held back until the turn settles, since the hub pushes a message once per id. Antigravity permission ids are agy-perm:<row>:<rpc>, and the rpc id may hold colons.
- `crates/engine/src/bridge/images.rs::to_jpeg`: Chat pictures are flattened onto white because JPEG has no transparency (else screenshots turn black), clamped to 16..1600 px, and refused by header before decoding when they claim too many pixels.
- `crates/engine/src/bridge/mod.rs::Router`: Requests are read field by field: a field of the wrong type counts as absent, as Swift did, and any JSON id is echoed back. Answers have sorted keys and whole numbers without a fraction. The phone's wire format is byte-compared with protocol/fixtures/.
- `crates/engine/src/bridge/net/access.rs::TunnelAccess`: Tunnel traffic arrives from loopback via cloudflared, so Cloudflare's headers are the only way to tell it from a local client. The pairing QR keeps v at 1 and every v1 field so an older phone ignores tunnel. The client secret stays in access.json.
- `crates/engine/src/bridge/net/address.rs::is_allowed`: Only loopback, 10/8, 172.16/12, 192.168/16, link-local and Tailscale (100.64/10, fc00::/7) may open a connection. An IPv4-mapped IPv6 peer counts as its IPv4 address for the limiter and audit log.
- `crates/engine/src/bridge/net/bridge.rs::halt`: Bridge-off first halts AuditLog and DeviceStore, which check a flag under their lock before each write, so nothing in flight (a hello, a pair, a revoke) writes after the switch goes off. Off binds no port, and a busy port is an error, never another port.
- `crates/engine/src/bridge/net/devices.rs::DeviceStore`: devices.json is byte-identical to Swift's JSONEncoder output (slash escaped) so either app reads it. Only token SHA-256 hashes are stored and compared in constant time over every device. lastSeen is written at most once a minute and a file in another format is never overwritten.
- `crates/engine/src/bridge/net/fetch.rs::fetch`: The Access-key fetch runs the name lookup on its own thread because the system resolver has no timeout. It runs only for a request carrying Cloudflare headers while internet access is on, and treats close without close_notify as a complete answer.
- `crates/engine/src/bridge/net/files.rs::sorted`: Bridge files in the Swift format need sorted keys written explicitly, because serde_json keeps insertion order once another crate turns on preserve_order. Dates are whole-second UTC iso8601, the only form Foundation reads.
- `crates/engine/src/bridge/net/frame.rs::decode`: The 256 KB message cap is enforced on the frame header, so a too-big frame is never buffered (close 1009). Clients must mask, and a request head too big or too slow gets a real HTTP status and is dropped.
- `crates/engine/src/bridge/net/identity.rs::BridgeIdentity`: The LAN certificate is read byte for byte from the Swift app's `identity.p12` and `identity.pass` (the Swift app deletes `key.pem`) so a paired phone's pinned fingerprint still matches; the bridge never makes or replaces one.
- `crates/engine/src/bridge/net/identity.rs::server config`: The certificate is served unparsed because macOS LibreSSL makes X.509 v1 and rustls's webpki check refuses v1; the phone pins the fingerprint, so don't add certificate validation.
- `crates/engine/src/bridge/net/jwt.rs::AccessJWT`: The Access key cache fails closed: a failed fetch serves cached keys only while under an hour old, an unknown `kid` refetches at most every 30 s, and the fetch runs without the lock.
- `crates/engine/src/bridge/net/limiter.rs::AuthRateLimiter`: Tunnel clients are keyed by `Cf-Connecting-Ip`, never by cloudflared's loopback address, and an IPv6 address counts as its /64, so a host can't dodge the backoff by changing addresses.
- `crates/engine/src/bridge/net/server.rs::BridgeServer`: A phone sends `hello` or `pair` within 10 s (pings don't count) and finishes the head within 5 s; one LAN address holds at most four unauthenticated sockets; pushes never wait on a slow phone, whose bounded queue marks it dropped.
- `crates/engine/src/bridge/net/server.rs::handlers`: Each text frame runs on its own thread (a `pair` blocks on the person, a reply on the terminal) with a per-phone cap; an accepted socket inherits non-blocking mode on macOS and must be reset.
- `crates/engine/src/bridge/net/wire.rs::Wire`: TLS reads take the lock only to feed rustls, and a read returns `Interrupted` when no plaintext has arrived so the caller rechecks its deadline; `shutdown` never waits, and writes go in pieces under rustls's 64 KB limit.
- `crates/engine/src/bridge/router.rs::interrupt`: Interrupts are limited to one per session per three seconds, since a second Esc would cancel the queued message.
- `crates/engine/src/bridge/router_ops.rs::photo and web ops`: A photo reaches a session only through the backend's acting call, so with acting off nothing is taken in; `web.snapshot` accepts only http(s) on localhost or 127.0.0.1 and gives the renderer the re-serialized URL without user info.
- `crates/engine/src/bridge/uploads.rs::PhoneImageStore`: Photos are saved as `phone-<8 hex>.<ext>` mode 0600 in a 0700 folder, named here and never by the phone, with the extension from magic bytes; an upload expires so trickling pieces can't keep it alive.
- `crates/engine/src/bridge/wire.rs::encode`: Text frames are JSON with sorted keys, unescaped slashes and whole floats written as integers, as the Swift bridge wrote them; binary frames are `PHN1`, `IMG1` and `WEB1` magic plus a big-endian u32.
- `crates/engine/src/catalog/claude_code.rs`: Claude Code's `additionalModelOptionsCache` in `~/.claude.json` is read only and never written; it is the fallback list when the live fetch fails.
- `crates/engine/src/catalog/claude_live.rs`: The live Claude list (`GET /v1/models`) only names models; the context window stays the data file's because the API's `max_input_tokens` differs. Errors name status or shape only, never the body or token.
- `crates/engine/src/catalog/claude_live.rs::refusal`: A 400, 403 or 404 from the models endpoint means it won't serve this login, so do not ask again with the same token (kept as a SHA-256 fingerprint); 401 and 429 pass with time and are retried.
- `crates/engine/src/catalog/live_cache.rs::put`: One process-wide lock covers the whole read-modify-write because several `LiveCache`s share the file; writes go to a uniquely named temp file then rename, and an older-than-a-day or clock-skewed entry counts as stale.
- `crates/engine/src/catalog/mod.rs::Catalog::load`: A user override file can fix a price, window or name but never adds a model to the allowlist; only built-in lists and what the tool reports live can.
- `crates/engine/src/catalog/roles.rs`, `delegate/role_models.rs`, `delegate/family.rs`: Roles are data (`picks`, `not_for` in `catalog.json`, overridden by model id) and only name a model for `delegate-models --for`; they never widen the allowlist. A family is the codename word with the version compared numerically (`family::parse`), so `gemini-4-hydrogen` and `gemini-4.1-hydrogen` match and `-xhigh` stays a variant. Codex's `upgrade` field in `models_cache.json` is read only if present (it is `null` today).
- `crates/engine/src/delegate/role_view.rs`, `catalog/override_file.rs`: What Settings > Skills & Models shows (`catalog.roles`). `role_view::views` reuses `role_models::resolve`, so the page and `delegate-models --for` cannot disagree; a pick is the user's (`Override`) when it is not in the built-in list, `Live` only when the marked model is gone, and a tool whose live list is empty (Antigravity's before a session reported it) is shown `checked: false` with the marked model, never as gone, but a pick the catalog's `not_for` excludes is never shown, live list or not. The override file is read afresh for roles but once at daemon start for prices and windows. JSON has no comments, so `override_file::ensure` makes `{}`.
- `crates/engine/src/catalog/mod.rs::borrowed price`: A Claude id newer than every known one in its family is priced and sized as the newest known one (`borrowed`), unless an entry made for that id says otherwise; a model with no price is unpriced, never $0.
- `crates/engine/src/catalog/mod.rs::price matching`: Claude prices match by id prefix, first match wins, so the longest prefix sorts first; a match must end on a `-` segment boundary (`fable-5-1` is not `fable-5-10`). Other tools match the whole id.
- `crates/engine/src/catalog/mod.rs::prices_hash`: The cost cache is repriced against the fingerprint of all price entries after the override merge; windows, names and model lists are not in it, so changing only those never reprices.
- `crates/engine/src/catalog/mod.rs::startable_shape`: A Claude model id goes onto a command line, so it must match lowercase ASCII plus an optional `[1m]` only; `model_key` cuts at the first `[`, so `claude-opus-5-5[1m] --flag` would otherwise pass.
- `crates/engine/src/contract/<tool>/support.rs`: One exhaustive `match` per tool with `#![deny(clippy::wildcard_enum_match_arm)]` and no `_` arm (a test reads the files for both); the lint fires only when the wildcard hides two or more variants, so the text check is what catches a single one. A line is a tooltip in Settings and a cell in the matrix: one line, 120 characters at most, never empty. A Gap names a phase (`phase 1: ...`) or, for the setup and version rows only, `design: 0019` or `design: version-sync`.
- `crates/engine/src/contract/gaps.json, unwired.json`: Only remove lines; `GUARD-PROVIDER-GAPS` refuses growth. Sorted, unique, one entry per line (`codex subagent.list`), in the lint baseline's `{"entries": [...]}` shape. `unwired.json` is exactly the Native and Fallback cells not in a provider's `WIRED`, so the PR that routes a cell cuts it from the file in the same change.
- `crates/engine/src/contract/<tool>/mod.rs::WIRED`: A cell joins the list in the PR that routes it through the registry, and needs a conformance check in `crates/engine/src/contract/conformance.rs` (or a `conformance_<area>.rs` beside it) by then, or `crates/engine/tests/conformance` fails with "is wired but has no conformance check". That test folder is written once; add checks in `src`.
- `crates/engine/src/contract/matrix.rs`: Iterates `Tool::ALL` and `Capability::ALL`, never a map, so the golden is the same on every OS. A change to any declaration changes `docs/provider-matrix.md`: regenerate it and read the diff.
- `crates/engine/src/contract/subagents.rs`: `Subagents` is the one port every provider gives (`list`, `glance`, `open`); `Registry::subagents` walks it depth first from the session (`MAX_DEPTH` 10, a `seen` set so a loop is listed once) and adds `flows::delegate_jobs` rows under every parent, so a row's `parent`, `depth` and `session` are the registry's, never a provider's. `Glance.recent` is a conversation tail (the app turns it into the doing line). Antigravity matches a parent's `invoke_subagent` roles to its children by order only when the counts agree, else it shows `agent_name`.
- `crates/engine/src/tools/agy/summaries.rs::with_copy`: The summaries copy is made and read under one lock (`rows_cached`, `children_cached`); reading it outside the lock while another call copies over it crashed SQLite (SIGBUS).
- `crates/engine/src/tools/agy/children.rs`: A child's status comes from the last 64 KB of its log (`send_message`, a last `ERROR_MESSAGE`) and the parent's last 256 KB (`[Message] ... sender=<id>`); a child that finished long before is `Quiet`, not `Completed`, once those lines fall out of the window.
- `crates/engine/src/tools/codex/children.rs`: The child index reads only a rollout's head (the first `session_meta`, 64 KB) and only when its size or mtime changed; `DayFolders` is the no-daemon fallback and reads at most two day folders; it reads each rollout's head once per process (`known_head`: a complete first line never changes; a missing or cut one is read again), since the registry asks it once per delegated Codex job on every load and 289 jobs re-read 2 day folders' heads each time (7.5 s a load). `ChildSource::done` ends one walk: a source that holds a connection drops it there. `tools/codex/list.rs::find_rollout` remembers what it found (checked with `is_file` on each hit); a miss walks the folders again.
- `crates/engine/src/contract/tool.rs`: `agy` is read (`Tool::parse`, serde alias) and never written; the wire name is `antigravity`. `catalog::Tool` is this type re-exported, so a new variant needs every `support.rs`, the conformance macro and `Registry::standard` and starts with no Gap.
- `crates/engine/src/cluster/core/`: `NodeCore::step` is sans-IO: it returns effects and does no I/O, and `Persist` is an effect the host must do and answer. The core cannot undo state after a failed save, so the host rebuilds the core from the last saved state. Every call is deduplicated by `(from, id)` for `DEDUPE_MS` and its result is cached, so a retry never runs twice. A call or message with an older term than the receiver's is refused with `stale_term` carrying the newer term and home, and a home that adopts a newer term emits `SteppedDown`. `adopt(term, sender)` takes a higher term only when its `n` fits a signed 64-bit journal column (`MAX_TERM_N`, which the state layer also enforces), is at most `MAX_TERM_STEP` (64) above the current one, and the sender is an Active member that may be primary (Can Be Master, or the home this node follows): the sender naming itself is enough, and a sender naming another Active member vouches for it (it could promote itself instead), so a node that missed a grant follows its old home to the newly promoted one; a Worker never moves a node's term (a node stranded behind a grant it missed is healed by its next `node.load` call to the old home, which the driver sends to every online peer every 30 s, or by a fresh link), and nobody moves a node to a term that names that node (its own term comes only from its own promote, which probes and confirms first). - `crates/engine/src/git/branch.rs`, `branch_file.rs`, `branch_parse.rs`: The branch comparison for the Changes panel (`read_branch_stat`, `read_branch_diff`, `read_branches`), over the same `command`/`run`/`drivers` as `read.rs`, so the same read-only flags, sandbox and timeouts apply; nothing here may run a git subcommand that writes. It diffs the working tree against `merge-base <base> HEAD` (`diff --name-status|--numstat -z -M <sha> --`), so it covers the branch's commits and uncommitted work in one list, and marks which files differ from HEAD (from `status`) so the answer can say it includes uncommitted work. The base is validated by `guard::clean_ref` (plain branch characters only, no leading `-`, no `..`) before anything runs, because it reaches git as an argument; an unknown base is `failed`, never a run with a guessed one. A repository with no commit, or with none of origin/HEAD, `main`, `master` sharing history with HEAD, answers with no base and no files, not an error, since the app asks every 5 s. Untracked files have no numstat, so their lines are counted by reading them (a symlink, a binary, a file over 2 MB or the 8 MB budget gives `null`). A rename is one `R` row with `from`; its patch needs `from` too, or it shows as a new file. Files are cut at 2,000 and the totals count all of them. `read_diff` shares `untracked_diff` and `patch` with `branch_file.rs`. `read_ref_stat` and `read_ref_diff` read one branch's committed work only, with no `status` and no untracked file: `ref_name` takes only a name `clean_ref` passes that starts with `refs/heads/` or `refs/remotes/`, the ref goes before `--` as a revision (after `--` git reads paths), and the diff runs from `merge-base <base> <ref>` to the ref; a ref with no base answers with its name and head and no files. `changed_at`, the newest modification time among the changed files (`symlink_metadata` on each path that passed `clean_path` and `stays_inside`, at most `MAX_FILES`, under the repository root that `rev-parse --show-toplevel` names, asked only when something changed), is filled by `read_status` and `read_branch_stat`.
- `crates/engine/src/git/worktrees.rs`, `refs.rs`: Pure parsers over text the daemon's reads print, so every format is fixed by the command that makes it. `parse_worktrees` reads `worktree list --porcelain -z` (attributes end in NUL, an empty attribute ends an entry; `locked` and `prunable` may carry a reason, which is dropped; a path keeps its spaces and newlines; `branch` has no `refs/heads/`; the all-zero `HEAD` of an unborn branch is `None`) and cuts at `MAX_WORKTREES` (50). `REF_FORMAT` separates fields with `%00` and a record is one line, so a subject cannot break a record; `parse_refs` skips `refs/remotes/<remote>/HEAD` before the `MAX_REFS` (300) cut and turns `committerdate:unix` seconds into milliseconds. The two count forms disagree on order and the parsers keep them apart: `%(ahead-behind:<commit>)` prints ahead then behind (`parse_ahead_behind`), `rev-list --left-right --count <base>...<head>` prints behind then ahead (`parse_left_right`); both print counts for histories with no common ancestor (git 2.54 prints `1 1`), so a count alone never proves a base (see `branch_list.rs`). `parse_shortstat` reads tokens, not the sentence: a binary-only change prints ` 1 file changed, 0 insertions(+), 0 deletions(-)` on git 2.54 and ` 1 file changed` on older ones, and empty text is all zeros. `remote_hosts` keeps a remote's name and its URL's lowercased host and nothing else (a user and a token in `https://me:ghp_x@github.com/o/r.git` are in no part of the result); the URL never leaves this function. `plain_label` makes other people's text a label: one line, control and bidi-control characters dropped, cut at `SUBJECT_CHARS` (120) on a `char` boundary; every subject and remote branch name passes it before it reaches a reply.
- `crates/engine/src/git/nearest.rs`, `branch_list.rs`: D1: a branch is merged into a base exactly when it is 0 ahead of it (the counts are read anyway for the nearest base), so nothing runs `for-each-ref --merged` or `merge-base --is-ancestor`; `merged_into` is checked against the integration branch first, then the default, and carries the rev, never the branch itself or a rev with its own short name. A base (the default, and the integration branch: the one the main checkout is on, when its name is not the default's short name) is never classified, because `main` would read "merged into agent-run-oss" and `agent-run-oss` "not merged, +1,482"; a base has no numbers. The default is often a remote ref (`origin/main`) while worktrees check out `main`, so names are compared by `short_name` (the longest matching remote prefix and `/` taken off). The nearest base is the candidate (default, integration branch, the branch's own upstream when it has another name; never the branch itself) with the fewest commits ahead, then the fewest behind, then candidate order, because one base for all would make every lane in a repository whose integration branch is 1,482 commits on `main` look like the whole branch. D5: a pick that is not 0 ahead is unconfirmed until something proves a common history (a 0-ahead pick needs no check: the head is in the base). `rows` takes two closures so it stays pure and the daemon decides when to read: `counts` and `lines` answer `None` for not known yet (the row is `pending`), `Some(None)` for no common history (`diff --shortstat` exits 128 "no merge base"; the candidate is dropped and the row is picked again), and `Some(Some(..))`. A row whose candidates are all unrelated has `base: null` and `unrelated: true`; a row with no candidate at all (it is the default or the integration branch) has `base: null` and neither flag. A pick 0 ahead that is not a merge base (its own upstream, say) gets zero `lines` without a read, a remote-only row is a base only when `<remote>/<name>` equals the base rev exactly, and a worktree with `work` is classified from it by the app, not here. One row per local branch, per remote-tracking ref whose name less its remote is no local branch's name (a remote ref the local branch of the same name hides is dropped), and per detached worktree.
