# The Rust app in one pass

The processes, the engine's modules, the app's areas, and where a new op, setting, event or area goes.

Part of the Rust app's notes, moved from `crates/AGENTS.md`; the index is in the root `AGENTS.md`. Keep it true: change the note with the code, and add what bites you under Things that bit before.

- **Processes.** `notchling-app` (app tier) and `notchling daemon` talk over the local API; the hook and the command line are agent-tier clients. The app starts the daemon from the `notchling` beside it, or the `dev.notchling.daemon` LaunchAgent that `notchling service` writes does. Phones reach the daemon's bridge (TLS on 47821, the tunnel origin on loopback 47822). `notchling-ptyhost` holds terminal ptys under the `local.agentconsole.hostd` LaunchAgent, which nothing here installs. The daemon owns everything that acts or lives long; the app reads transcripts itself, read-only, for speed (decision 0004). `notchling-embed` (`crates/embed`) is a helper the daemon starts only while Semantic Search is on and Granite is on disk: `serve --model <dir>`, JSON lines over stdin and stdout, and it exits after 300 s idle or when stdin closes. The bundle carries it in `Contents/Helpers` (`tools/bundle-next.sh`, signed `dev.notchling.embed`).
- **Engine.** Pure where it can be: planners return a plan; effects sit behind traits with fakes (`Launcher`, pty, Keychain, HTTP, spawners). `transcript` (Claude Code, Codex rollouts, ACP, the phone's chat view, subagents, shells; `locate` finds a file and its `/clear` successor), `sessions`, `terminal` (emulator, `ask_dialog`, `permission_dialog`, keys, `pty/`), `reply` (keys and timings pinned to the Swift app by `pin_tests.rs`, but a reply's paste and Enter wait on the input box, `terminal/input_box.rs`), `control` (new, stop, remove, move, Move All, Trust Folder, slash commands), `git` (a session folder's status and diff, read only, for the Details Panel's Git section), `tools` (`codex`, `agy` over `acp`), `delegate`, `bridge` (router, hub, `net/`) and `viz`, `pages`, `search` (`fts.rs`: `daemon/search.db`, FTS5, bm25), `accounts`, `providers`, `lanes`, `limits`, `cost`, `catalog` (`data/catalog.json` and live lists, decision 0016), `vault`, `machines`, `install`, `settings` (`keys.rs` lists every key), `store` (`notchling.db`) and `docfile` (decision 0014).
- **App.** Each area keeps a pure model, tested everywhere, beside GPUI views under `#[cfg(target_os = "macos")]` (`view*.rs`, `window.rs`) and `src/mac/` (shell, tray, Dock, hot key, `--render`). Areas: `chat/` (`chat/view/tool/`: one adapter per tool behind `ChatTool`, decision 0015), `notch/`, `search/` (a global hot key, ⌃⌥P by default and set in Settings > Search Shortcut: `search/shortcut.rs`, stored as `searchShortcut` like `ctrl+alt+p` or `off`; ⌘⇧P is only an in-app key binding, `OpenSearch` in `mac/dock.rs`, because a system hot key reaches Notchling before any app and took VS Code's Command Palette), `pages/` (`wry` windows and Chat's page panel, decision 0013), `accounts/`, `vault/`, `phone/` (pairing over `bridge.*`), `sheets/` (New Session, Settings, Second Opinion), `tools/` (Codex, Antigravity), `welcome/` (first run, About, updates, Install Hook), `switches/`, `machines/` (`notchling-machines`: no ssh or `gh` without `--live`, no vault value without `--vault`). `session_source.rs` gives Chat and the notch their rows from a background thread; UI threads never touch the socket. `actions.rs` sends ops; session calls wait `SESSION_CALL_TIMEOUT` (60 s). Daemon calls block: make them off the UI thread.
- **Where new things go.** An op: its name in `crates/local-api/src/wire.rs`, served from `crates/notchlingd/src/<area>_ops.rs` (an `OpGroup` added with `Ops::with_group` in `daemon_wiring.rs`) with the narrowest `OpSpec`, behind its switch, tested in `<area>_ops_tests.rs`, read in the app's `<area>/wire.rs`. Work that can outlast 5 s answers at once and sends its result as an event (`accounts.result`, `accounts.done`). The local API and the phone protocol change additively only. A setting: its line in `engine/src/settings/keys.rs` with its class for agents, title and description, and, if the app must apply it at once, a line in `ChatView::applied_setting` (`chat/view/sheets.rs`), which both the Settings sheet and the daemon's `settings.changed` reach; a setting that is the app's as a whole, not Chat's (`appearance`, `searchShortcut`), goes in `mac::settings_live::app_wide` instead, which also runs with Chat closed. A view: a pure model, a GPUI view, a `ViewSpec` in its area's `renders.rs` and an arm in `mac/views.rs`. An engine part: pure planners, effects behind a trait. Skills: `add-provider`, `fix-bug-reproduction-first`.
