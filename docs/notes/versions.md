# Tool versions

The Mac as the reference for Claude Code, Codex, Antigravity and Notchling versions, and how workers follow it.

Part of the Rust app's notes, moved from `crates/AGENTS.md`; the index is in the root `AGENTS.md`. Keep it true: change the note with the code, and add what bites you under Things that bit before.

- **Versions** (`engine/src/versions/`, `notchlingd/src/versions_ops.rs`, `app/src/machines/versions_*.rs`, `app/src/sheets/client_*.rs`; [design](../superpowers/specs/2026-11-13-version-sync-design.md), decision `tool-versions-follow-the-mac`). The Mac is the reference for Claude Code, Codex, Antigravity and Notchling versions; phase 1 only sees. The Mac's versions come from files, never a process, except `agy --version` at most every 10 minutes (`CAP-PROCESS`; agy 1.5.9 prints a bare `1.5.9` and older builds `agy 1.4.2`, and `cli_output` takes both for agy and only the prefixed form for Codex and Notchling); `versions.get` is agent tier and Machines (a separate binary) asks the daemon rather than read them. A worker's tools are read by Machines' read-only Tool Versions step (no `--version` for agy, no installer, no Fix) and saved to the `versions/workers` document in `notchling.db`, which `versions.workers` serves to Settings. A version is only ever a strict `x.y.z[-pre]` of at most 32 characters. A mismatch warns, never refuses. Nothing installs or changes on a worker. Phase 2 checks a new Mac version with files and flags only (`versions/check.rs`: `--version`, `claude doctor`'s auto-update line, `codex exec --help`'s flags, and a strict pass over recent transcripts that counts what the lenient readers skip), and the answer is always Partly Checked, never Passed: screens, dialogs and turns are not exercised. A passing version becomes the reference (`versions/reference.rs`), which workers compare with; a failed one is kept, raises an inbox notice and is never a target. The soak (`versions/soak.rs`) counts unknown transcript lines on real sessions under the reference and gates nothing. Latest reads the vendor's newest version over `curl` (`CAP-NETWORK`, cached an hour); Update and Go Back run the method's own update on the Mac only, behind the `install` switch (`CAP-PROCESS`), and Go Back only where the method can install an exact version. Phase 3 keeps workers where they are. Machines' Self-Update Off steps (`machines/steps_selfupdate.rs`, one per installed tool, Cadence::Slow) turn a tool's own updating off on a worker with one key: `env.DISABLE_AUTOUPDATER` in Claude Code's `settings.json` (`CLAUDE_CONFIG_DIR` and each lane's folder too), `check_for_update_on_startup = false` in Codex's `config.toml` (`$CODEX_HOME` first), and `DISABLE_AUTOUPDATER=1` in the sd service files (`service_files.rs`). The Antigravity and Codex `daemon_auto_start` knobs are detect-and-repair only until `AGY_KNOB_VERIFIED` and `CODEX_DAEMON_KNOB_VERIFIED` (`versions/knob.rs`) are turned on by hand after a real worker run. A write is a plan the user sees (exact lines, no file content), one click, a SHA-256 check against the file the plan read, a 0600 backup beside it (newest 5 kept) and a temp file moved over the original (`machines/remote_edit.rs`); Self-Update On takes back only a value Notchling set (a button on the step, and `SetupEngine::undo_self_update` for a whole machine; the Remove alert names what is still off but does not run it). Each Fix is one line in the `versions/selfupdate-log` document (last 200), which the daemon copies to `audit.jsonl` once (`Fact::SelfUpdate`). Drift (`versions/drift.rs`, `notchlingd/src/versions_drift.rs`) is a worker whose installed version differs from the Mac's usable reference; it is noticed once per machine, tool and found version (`versions/drift-noticed`), raises an inbox notice (`version_drift`) and withdraws it when they match again. Behind and ahead are both drift, and nothing is moved by it.
