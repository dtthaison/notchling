# Logging, Phase 1: the Registry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new leaf crate `crates/events` (`notchling-events`) holds the envelope, the closed list of field types, every kind of the first registry with its texts, a test sink, the golden and `docs/log-kinds.md`, plus the decision record and two lint rules. Nothing writes an event yet: no behavior changes.

**Architecture:** `kinds!` (a `macro_rules!` in `kind_macros.rs`) declares each kind once and makes its typed struct, its `KindSpec` and its group list. Fields accept only types that implement the sealed `LogField` trait (`field.rs`, `field_ref.rs`); `log_choice!` (`field_macros.rs`) declares choice enums. `Emit` is the trait every producer will call (`push`, `commit`); `MemorySink` is its test double. `doc.rs` renders the registry as Markdown and as the golden JSON.

**Tech Stack:** Rust 1.99.1, `serde`, `serde_json`, `sha2` 0.10, `base64` 0.22 (all already in `Cargo.lock`); Python 3.9 standard library for the guard.

**Spec:** `docs/superpowers/specs/2026-11-13-logging-design.md` (branch `agent/logging-design`), sections 6.1 to 6.5, 17 (Phase 1). Read sections 6.2 and 6.3 before Task 1.

**Branch:** `agent/logging-p1-registry`, from `origin/merge/settings-batch` (cc28da7 or later).

## Global Constraints

- No comments in code, doc comments included. The why goes in `crates/events/AGENTS.md` (new) and `crates/AGENTS.md`. `python3 tools/strip_comments.py --check` must pass.
- No field type can hold free text. The allowlist is exactly the spec's 6.2 list plus `Hex` and `KindName` (call C8): `Choice`, `Flag` (`bool`), `Count`, `Bytes`, `Tokens`, `Millis`, `Time`, `Money` (integer micro-dollars), `Percent` (0 to 100), `Version` (`[0-9A-Za-z.+-]`, at most 32), `Op`, `ErrorCode`, `Exe` (`[A-Za-z0-9._+-]`, at most 64), `Tool` (`[A-Za-z0-9_:.-]`, at most 64), `CodeLoc`, `Seal` (base64, 44 characters), `Hex` (lowercase hex, 8 to 64), `KindName`, `Ref<T>` (at most 256 characters, no control characters), `Option<T>`, `List<T>` (at most 16 items).
- An event is at most 4 KB as JSON.
- Kind names match `^[a-z]+(\.[a-z_]+)+$`; titles are Title Case, at most 40 characters; `records` and `why` are one or two sentences, at most 200 characters, ending in a period.
- `kv` starts at 1 for every kind. `v` (the envelope) is 1.
- Files under 1,000 lines (warning at 600): one kinds file per group.
- Licenses: only crates `deny.toml` allows; this phase adds no new crate to `Cargo.lock`.
- Tests never touch the Keychain, `~/Library/Logs`, `~/.claude`, the real data folder or the network.

## Review Focus

1. A choice value the registry doesn't list arriving later as a string (from `log.emit` in Phase 5): it must become `other`, never fail the whole event. (Task 1 test `choice_from_unknown_name_is_other`.)
2. A `Ref` id with a newline or 300 characters (session ids come from files anything can write): it is cut to 256 and control characters are replaced, so a line can't be split. (Task 1 test `ref_drops_control_characters_and_cuts_at_256`.)
3. An `Exe` from a path such as `/tmp/a b/evil;rm` or a name with a space: only the file name is kept, and a name outside the charset becomes `unknown`. (Task 1 test `exe_keeps_file_name_and_charset_only`.)
4. Two platforms writing a different golden: `serde_json`'s `preserve_order` is on for macOS (through GPUI) and off on Linux, so the golden and the field writer must not depend on map order. (Task 2 test `fields_write_in_name_order`; Task 4 runs the golden test on Linux CI as well.)
5. A list field of 40 secret names: cut to 16, and the event stays under 4 KB. (Task 2 test `list_is_cut_at_16_and_event_under_4k`.)
