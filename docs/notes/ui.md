# Views, the kit and words

Words from `locales/`, the kit, Appearance, popup menus, the ? render map, and GPUI's surprises.

Part of the Rust app's notes, moved from `crates/AGENTS.md`; the index is in the root `AGENTS.md`. Keep it true: change the note with the code, and add what bites you under Things that bit before.

- **Words.** A view's text is a `notchling_locale::Text` from a `locales/en/*.ftl` message, in an area `tools/locale/areas.json` marks moved (`LINT-LOCALE-LITERAL`); a draw reads a plain message (`Text::get`), and a message with variables is formatted in a model compute. `app::language::start_for_run` (and `start_for_render`) picks the language at every entry point (`mac/shell.rs::run`, `machines/window.rs::run_command`, `--render`, which ignores the system's list). `NOTCHLING_LOCALE=<tag>` chooses a shipped language, `en-XA` a pseudo-language that accents, lengthens and brackets every message, and `NOTCHLING_LOCALE_MARK_FALLBACK=1` brackets messages that fell back to English. `platform::locale` reads the system's languages and region.
- **Kit.** Views use its tokens (`Ink`, `TypeRole`, `metric`, `Motion`, `Icon`), never a raw color or size. Icons are vendored Lucide SVGs (ISC), never SF Symbols, which may ship only on Apple's systems. Tag views with `.part("Name", …)` for the ? button; grep the name the user gives.
- **Appearance setting** (`appearance` key, Settings > General > Appearance: System, Light or Dark; `app/src/appearance.rs`, `mac/appearance.rs`, `kit/src/appearance.rs`). `kit::Preference` is the pure choice (`resolve(system)`) and a process-wide atomic (`set_preference`/`preference`) holds it; `kit::ui::window_appearance` is the one place a view learns its look and returns the forced one or the window's, so a view never reads `window.appearance()` itself (a new window asks `window_appearance`, not NSAppearance). The native look (title bar, traffic lights, menus, scroll bars, the tray menu, the `wry` pages and their `prefers-color-scheme`) comes from `NSApp.appearance` (`mac::appearance::set_native`; nil for System). Setting it makes AppKit send `viewDidChangeEffectiveAppearance` to every window, and GPUI's `observe_window_appearance` is how each window, and Chat's cached parts through `redraw_parts`, redraw once: a system change and this setting take the same path, so a new window or part observes it the same way. It is read once in `shell::run` before any window opens and applied by `mac::appearance::on_change`, which `mac::settings_live::app_wide` calls from `ChatView::applied_setting` (the Settings sheet's `SettingChanged` and an agent's `settings.changed` both reach it, so either change applies at once, with Chat closed too); the NSApp call goes through `cx.spawn` because AppKit calls GPUI's observer synchronously and a call inside a click handler would borrow the app twice. The notch draws `Appearance::Dark` always (`notch/cards.rs::A`) and ignores the setting. `NOTCHLING_RENDER_APPEARANCE_SETTING=system|light|dark` sets it for a `--render` (`NOTCHLING_RENDER_APPEARANCE` still stands for the macOS look).
- **Popup menus** (`kit/src/ui/menu.rs`, tokens `MENU_*` in `kit/src/metric.rs`): one look for every list of actions or choices in a floating panel, taken from the model picker: `menu_panel` (hugs its content, `MENU_MIN_WIDTH`..`MENU_MAX_WIDTH`) or `menu_panel_wide` (fixed `MENU_MAX_WIDTH`, for notes and details that wrap: text that wraps needs a width before layout, and a hugging panel gives none, so the wrapped lines overlap the row under them), `MenuItem` rows (Meta type, 8 x 3 padding, Raised wash, check or chevron at the right end, `held` for an off row) and `menu_rule`/`menu_section`/`menu_note`. Don't give a rule `w_full` inside a hugging panel (a percentage of an unsized width is 0). Views never size a menu themselves; the picker, + menu, account menu, row and Copy menus, command list, simulator device menu and the Accounts window's row menu all use it. `NOTCHLING_RENDER_ACCOUNT_MENU=1` and `NOTCHLING_RENDER_ROW_MENU=job|confirm` open the last two for a render.
- **Render map.** While ? is on, Chat draws outlines and badges (`chat/view/render_map.rs`, pure half `kit/src/render_map.rs`): one color per region that draws alone (Sidebar, conversation, Details Panel), one shared color around what the root draws every frame (header, reply box, Tasks bar, terminal, simulator and page panels). A badge shows the region's draws since ? came on (the conversation's also the rows its last draw built) and flashes for 300 ms when it drew.
- The root draws the map, over the parts, never inside one (a badge in a cached part would draw it and falsify its count). The badge is a canvas that reads the `pane.rs` counters as it paints; one timer redraws only the chrome to clear a flash, and that draw is not counted. A new window-drawn panel gets `.window_region(a, cx)` before its part tag.
- `NOTCHLING_RENDER_PARTS=1` shows the map in `--render chat`; `NOTCHLING_RENDER_MAP=0` keeps the names but not the map, to compare. `bench_chat.rs` holds that the map changes no part's count.

## Things that bit before

- GPUI 0.2.2's text element truncated its runs in place, so a resize measured an elided label again and sliced a string mid-character: a crash. `vendor/gpui` fixes it; its `NOTCHLING.md` says when to drop the patch.
- GPUI's `truncate()` never draws the ellipsis (`nowrap` keeps the first measurement). Use the kit's `elide()`.
- GPUI swaps a state's whole text style on hover and press, so a hover that set only a color made the words grow. Give each state the full style (kit buttons do).
- GPUI sets the arrow cursor after every draw when nothing asks. Clickable elements need `.cursor_pointer()` (kit buttons have it); resize cursors come from `kit::ui::resize_edges`.
- GPUI resigns a window that became key while the app wasn't active with the window's lock held: the app hung. Call `cx.activate(true)` before opening a window from the menu bar.
- Every pixel of a GPUI window is Metal drawables plus MSAA textures: a screen-wide notch canvas cost 93 MB. `notch::layout::canvas_size` sizes it to the largest shape.
- The terminal panel's cursor covered the last typed letter (`clea` and a blue block over the `r`): a row was drawn as one flowing text per style, so a prompt glyph (`❯` came out 0.7 cell wider than its cell) moved the rest of the line off the grid while the cursor stayed on it, and the block was an opaque box over the text. Each span now sits at its own column, the cursor is the cell's letter inverted on a block (`chat/terminal_paint.rs`), and a wide cell gets a two-cell cursor. The emulator's cursor column was right all along: compare it with where the glyph is drawn before suspecting the emulator.
