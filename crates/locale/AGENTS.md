# notchling-locale: notes for agents

The words the Mac app shows, in the language the user chose. English lives in `locales/en/*.ftl`; `tools/locale/gen.py` writes `src/generated.rs` from it and from every shipped translation; this crate picks the language at start and formats a message. The design is `docs/superpowers/specs/2026-11-13-localization-design.md`; translators read [docs/translating.md](../../docs/translating.md). What a change could break without knowing it, by file:

- `src/generated.rs`: Written by `python3 tools/locale/gen.py`, never by hand (`GUARD-LOCALE-GEN`). A `Text` is a position in the sorted keys of English, so adding or removing a key renumbers the ones after it: nothing may store a `Text` as a number (a file, the wire, a setting). It sits under `#[rustfmt::skip]` because its lines are long and not rustfmt-stable, and is exempt from the file size lint by path.
- `src/format.rs`: `Text::get` is a plain lookup and costs nothing per draw. A message with variables is formatted with `format`, in a model compute, never in a draw. `lookup` finds plain messages only (no variables, no plural); a log kind or a Settings entry read by name goes through it. A `Num` saturates at the ends of `i64` and an `f64` that is not finite formats as 0.
- `src/state.rs` and `src/choose.rs`: The active language is a `OnceLock`, set once by `start` (or `apply`) before any window opens; a read before that answers English. A second `apply` is refused, so a test that needs another language runs in its own process (`tests/apply_once.rs`, `tests/before_start.rs`). Every entry point calls `start`: `mac/shell.rs::run`, `machines/window.rs::run_command` and `--render` (`mac/render.rs`), through `crates/app/src/language.rs`. A new entry point that opens a window without one shows English and nothing says so.
- `src/choose.rs`: The order is `NOTCHLING_LOCALE`, the saved setting (`system` or none means skip it), the system's list, then English. A tag chooses the language it names, else its parent (`pt-PT` to `pt`), else the next tag in the list; only a shipped language counts (`draft` ships nothing). `en-XA` is the pseudo-language and is chosen only by the environment, never by the system list. Under `--render` the system list is not read, so a render never depends on the Mac's settings.
- Fallback: a message a language lacks falls back to its parent and then to English, per message. The fallback and pseudo caches each leak one string per message once, for `&'static str`; this is bounded by the number of messages. `NOTCHLING_LOCALE_MARK_FALLBACK=1` wraps a fallen-back message in `‹ ›`, to find what a translation still lacks.
- `src/numbers.rs` and `src/fmt.rs`: Plural categories and digits come from ICU4X (`icu_plurals`, `icu_decimal`, pinned to one version, `icu_provider` with `sync` since `PluralRules` is not `Sync` otherwise). The compiled data adds about 125 KB to the release app (measured: 28,651,840 to 28,779,936 bytes). `fmt::count`, `decimal`, `list` and `join` are the only places a number or a list is turned into text; a view never formats one by hand.
- `src/pseudo.rs`: Accents the message's own letters (not the values of its variables), pads it with `~` to 140% of its length and wraps it in `⟦ ⟧`. A UI that clips or overlaps in `en-XA` would do the same in German.
- `src/testing.rs`: Hidden from the docs, for tests of other crates (`messages`, `plural_categories`, `reachable_categories`). Not for the app.
- `src/conformance_tests.rs` and `tests/fluent_ref/`: The conformance test is the referee for our parser. It reads the same `.ftl` text with `fluent-bundle` (dev only, never a dependency of the app) and fails when its output differs from ours for any message in the fixture tree or for the sample numbers. When it disagrees with the generator, the generator is wrong, unless the construct is outside the subset the guard allows.
- `Cargo.toml`: ICU4X and the Fluent crates are pinned with `=`; `cargo deny check` allows their licenses (Unicode-3.0 among them). Bumping one means re-running the conformance test and the size measure above.

## Registries

Designs that build on this crate keep their words as messages and never copy them into code:

- Settings search entries hold `Text` constants from `t::settings` and live in the app (calls P5 to P7), so a title and its search words come from the same message as the row.
- Log event kinds are `logs-event-<kind>`, `logs-event-<kind>-about` and `logs-event-<kind>-why` in `mac/logs.ftl`, read through `t::lookup` by name (call P8). A kind with no message shows its raw name.
