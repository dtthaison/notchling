# Outbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Messages sent to a session from Chat, the notch or the phone are saved in `notchling.db` first, delivered by one postman per session as soon as the terminal would take them, in order, and never typed twice; Send returns in milliseconds.

**Architecture:** A pure core in `engine::outbox` (the row model, its SQLite store, the gate that decides "type now, wait, or ask the person", the outcome and verification rules) plus two transcript readers (`count_since`, `queue_state`). `notchlingd` runs one postman thread per session with rows, through a courier per tool (Claude Code typed through a reused `claude attach`, Codex and Antigravity through their runners), serves the additive `session.send` and `outbox.*` ops and the app-tier `outbox` topic, and keeps `session.reply` for old callers on top of it. The held-text path is removed. Chat draws Outbox rows as bubbles with their actions.

**Tech Stack:** Rust (engine, notchlingd, local-api, events, platform `watch`, GPUI app), rusqlite, Fluent locale files.

**Spec:** `docs/superpowers/specs/2026-11-15-outbox-design.md`. Every task's implementer reads the sections its task names. Sections 7.1 to 7.5 are decisions; "Builder's call" items are settled and not reopened. The maintainer answered the spec's question 1 on 2026-11-15: a message only in Claude Code's queue is not Sent; its row stays `in_queue` ("Queued in the session") until the model takes it. The rulings that follow from it (R1 to R11), and those from the plan review of 2026-11-15 (R12 to R22: merged prompts are taken, the `in_queue` watch's exact terms, which couriers verify, the `gone` re-check, `New.clear_box`, `None` baselines, one shared `SafeModes`, `OutboxOps` notes and resume, the gate order, a vanished job's grace, the race test's invariant), are in `docs/superpowers/plans/2026-11-15-outbox.ledger.md` and are not reopened either. Each is written into the task it changes.

**Base and branch:** build on a branch `agent/outbox` from the latest `origin/agent-run-oss` (at least 5f48fb0c, which holds `agent/held-busy-background` and `agent/reply-leftover-box`). Never commit to `agent-run-oss` or `main`.

## Review Focus

1. A daemon killed while a row is `sending`: on start the row is Sent if the transcript shows the model took it, Queued in the session if only Claude Code's queue holds it, else May already be in; never typed again on its own. (Task 11 `sending_row_found_at_start_is_deleted`, `sending_row_enqueued_only_at_start_is_in_queue`, `sending_row_not_found_at_start_is_unsure`, `sending_row_without_seen_before_is_unsure`.)
2. Two identical short messages ("ok", "ok") sent back to back to a working session: both delivered, each confirmed by its own transcript line, neither confirmed by the other's. (Task 3 `counts_each_copy_after_since`; Task 11 `second_identical_row_needs_its_own_line`.)
3. A session whose input box holds text the person typed: nothing is typed, the row shows the text with Clear Box and Send, and the session's later rows wait behind it in order. (Task 10 `foreign_box_text_stops_at_box_with_text`, `rows_behind_a_box_head_wait`.)
4. A slow or hung attach to one session while another session has a message: the other is delivered at once. (Task 7 `locks_are_per_session`; Task 10 `slow_session_does_not_hold_another`.)
5. Edit or Remove pressed in the same instant the postman takes the row: a take always gets a consistent text and an edit never changes text already taken (an edit that lands first returns the row to `queued` and the take then takes the edited text; one that lands second is refused `Busy`); a lost take types nothing (R22). (Task 2 `take_and_edit_race_one_wins`; Task 9 `edit_on_sending_row_fails_being_sent`.)
6. A row only in Claude Code's queue is never Sent, and comes back as May already be in if Claude Code drops it (a restart, a `popAll`, a `remove`) before the model takes it. (Task 3 `pop_all_and_remove_count_in_neither`; Task 5 `left_queue_untaken_for_30s_is_unsure_dropped`; Task 11 `enqueue_only_goes_in_queue`, `in_queue_dropped_by_restart_is_unsure`, `in_queue_popall_without_take_is_unsure`, `dropped_verdict_runs_at_30s_without_file_change`.) A merged prompt is a take, so such a row is Sent (R12; Task 3 `merged_user_line_counts_as_taken_for_each_entry`).

- Create: `docs/decisions/XXXX-outbox.md` (Status: Proposed). `XXXX` is a placeholder; the number is assigned at merge, in merge order, and the merging PR renames the file and every reference.

- [ ] **Step 1: Write the record** in the template of `docs/decisions/README.md` (Context, Decision, Consequences). Decision bullets, one line each:
  - Messages to a session are saved in a Node-class `outbox` table in `notchling.db` before anything is typed; Send returns the row id at once.
  - One postman per session delivers in order; only it types a message into a session; acting ops lock per session, not globally.
  - Deliver like the terminal: type mid-turn; wait only for a dialog or an earlier prompt unread in Claude Code's queue; slash commands, Codex and Antigravity wait for the turn end; the safe rule (turn end) when the queue lines can't be read.
  - Never twice: Sent only when the transcript shows the model took a new copy since the try began (a user line or `queued_command`); a copy only in Claude Code's queue keeps the row as In Claude Code's queue; otherwise May already be in, decided by the person.
  - The Outbox is a mailbox: a row is deleted when settled; unsent rows are never deleted silently and are raised once in the Inbox after 7 days.
  - `session.send`, `outbox.*` and the app-tier `outbox` topic are additive; `session.reply` runs on the Outbox; held text and `session.held` go.
